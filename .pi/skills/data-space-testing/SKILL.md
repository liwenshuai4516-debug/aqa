# 数据空间测试数据规范

数据空间保存用例台账和执行流水；UI/API 原工作流持有资产、批准及执行证据。本 Skill 规范两者交接和 Agent 输出，复用现有工具，不创建另一份结果库、runner 或批准路径。只读整理不自动绑定、执行或回写；用户已要求回写时在该范围内完成，无需逐条重复确认。

## 先定位，后交接

1. 开始新测试时，调用 `data_space_automation` 的 `initialize`，传 `engine` 和用户的 `targetUrl`（或明确的 `systemId` / `envId`），从结构化回执取得项目、环境 ID、`baseUrl`、非敏感 `parameters` 和 `privateParameterKeys`。`missing-environment` 时在数据空间补齐配置后重试；`ambiguous` 时用候选真实 ID 消歧，不能套用默认项。只读查询不初始化通道。
2. `configured` 只表示配置匹配，不代表网络或登录成功。UI 录制前检查当前工作区 Playwright 依赖、配置的 testDir / project / baseURL 与相对 seed 路径，先收集 seed，再由浏览器确认目标页面和登录状态。把返回参数按业务含义用于测试数据；不得当作脚本或任意进程环境变量执行。API 仍走原生目标许可与预检。已有配置冲突时明确修正，不能悄悄切换目标。用例范围通过 `data_space_cases` 查询，优先真实 ID；`get` 不按 project 消歧，前 100 条不是全量。
3. 保留本次取得的 `revision`、用例引用和原生资产／批次引用。聊天锚点只帮助定位，不是版本锁或结果证据。写前发现用例已变更，先核对对应测试版本；原生关联过期需重新关联，不能把旧结论贴到新用例上。

数据空间在同一 dataDir 内跨工作区共享，项目名、环境名不能单独充当全局身份。敏感参数只返回脱敏占位或名称；不使用 `***` 执行，不把密钥、cookies、storageState 或连接口令写进备注与结果。执行凭据沿用原工作流的私有引用。

初始化成功即建立持久通道。默认归档到对应项目的“自动化测试 → UI/API 自动化导入”；有明确归属时在初始化传入回执中的真实 `featureId`。通道仅含工作区、引擎、项目、环境和归档位置，不复制环境参数。环境改动后重新初始化；`disconnect` 加 `engine` / `envId` 停止该通道的新资产归档，已绑定用例的结果同步仍沿原绑定（停止须逐项 `unbind`）。同地址多个通道不能自动判断归属，先断开非本次通道。

## 按来源选择唯一写入路径

| 输入／意图                                 | 操作与边界                                                                                                                                                                                                                                   |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新生成原生资产                             | UI `candidate` 成功、API `review` / `asset_import` / `asset_restore` 返回资产后，宿主按已初始化通道自动归档。用 `import` 加 `engine` / `assetRef` 核对回执或补漏，不执行测试。仅 `save-cases` 的未组装草稿保留在原工作流，形成资产后才归档。 |
| 已有 UI/API 原生批次                       | 查询原工作流证据；用 `data_space_automation` 的 `sync`，传 `engine` 和原 `runRef`。不要再用普通登记重复写一次。                                                                                                                              |
| 关联自动化资产                             | `inspect` 读取资产后，`bind` 传 `caseId`、`engine`、`assetRef`、`nativeCaseId`、`envId`。UI 引用为真实 `{path,sha256}`，API 为原生资产摘要；绑定由宿主生成版本指纹。                                                                         |
| 执行已关联用例                             | `route` 传 `caseId`，读取返回的全部 `scope.nativeCaseIds`，核对整个资产的执行范围，再调用返回的原工具及参数。按需加载 UI/API 阶段 Skill，台账“已评审”不代替原批准、诊断或预检。                                                              |
| 无原生批次的已观察结果                     | 仅在用户要求登记时使用 `data_space_record_result`；按项目、环境和实际批次分组，每个用例一条。只传公开 schema 支持的字段和结论，不伪造 `source=automation`。                                                                                  |
| 无原生资产引用的草稿、推测或无法匹配的数据 | 结构化列为未入库项，说明缺口。不创建占位用例、环境或成功记录；用例归档仅接受宿主核验的原生资产。                                                                                                                                             |

原生用例导入为草稿；原生资产每个修订单独保留，同一工作区／引擎／资产引用／环境／原生用例重复导入不增行，不覆盖人工编辑。完整步骤、断言和来源以原生资产为准，台账字段受长度上限约束。API 只有形成已评审的冻结资产才能导入，不把尚未冻结的候选伪装为资产。

原生执行完成后宿主自动同步，宿主重启或插件实际重新加载可补同步（设置开关不是服务端重载）。取消或通知丢失时查询原批次，再按原引用 `sync`；同步不重新执行业务。核对 `imported`、`duplicate`、`errors`、`unmatched`：`ok=true` 且导入数为 0 不证明目标用例已入库；部分失败逐项保留。原生同步按工作区、引擎、run 和台账用例去重，子集重跑不补写未选中的用例。

普通登记是追加流水，**没有幂等请求键**；返回不明先核对执行结果页，不盲目重发。任务名相同不会合并任务。公开 schema 当前只接受“通过／失败／阻塞”；跳过、取消、未执行、不稳定、未知保留在交付中，不改名挤入接口。人工／AI 登记没有原生证据核验和版本比较写入保证。

## 结构化结果输出

需要整理、同步或回写结果时，读取 [结果交付约定](references/result-output.md)，按一次真实原生 run 或一次人工登记批次输出 JSON；纯用例／环境查询可直接简答。该 JSON 是交付格式，不是新工具参数或 `runs.json` 的文件格式。批次引用、用例结果、同步回执、证据完整性与报告评审分别表达，未知值保留 `null` 和具体原因。

交付前核对：范围是否完整；用例／环境是否唯一；结果是否来自本次证据；状态及统计是否保留全部分母；写入回执是否逐项核对。失败原因只写证据支持的事实，推测明确标注。原始失败、父批次及过期结果保留，不用新成功覆盖历史。
