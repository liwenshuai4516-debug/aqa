# 数据空间测试数据规范

数据空间保存用例台账和执行流水；UI/API 原工作流持有资产、批准及执行证据。本 Skill 规范两者交接和 Agent 输出，复用现有工具，不创建另一份结果库、runner 或批准路径。只读整理不自动绑定、执行或回写；用户已要求回写时在该范围内完成，无需逐条重复确认。

## 先定位，后交接

1. 开始新测试时，调用 `data_space_automation` 的 `initialize`，传 `engine` 和用户的 `targetUrl`（或明确的 `systemId` / `envId`），从结构化回执取得项目、环境 ID、`baseUrl`、非敏感 `parameters` 和 `privateParameterKeys`。`missing-environment` 时在数据空间补齐配置后重试；`ambiguous` 时用候选真实 ID 消歧，不能套用默认项。只读查询不初始化通道。
2. `configured` 只表示配置匹配，不代表网络或登录成功。UI 录制前检查当前工作区 Playwright 依赖、配置的 testDir / project / baseURL 与相对 seed 路径，先收集 seed，再由浏览器确认目标页面和登录状态。把返回参数按业务含义用于测试数据；不得当作脚本或任意进程环境变量执行。API 仍走原生目标许可与预检。已有配置冲突时明确修正，不能悄悄切换目标。用例范围通过 `data_space_cases` 查询，优先真实 ID；`get` 不按 project 消歧，前 100 条不是全量。
3. 保留本次取得的 `revision`、用例引用和原生资产／批次引用。聊天锚点只帮助定位，不是版本锁或结果证据。写前发现用例已变更，先核对对应测试版本；原生关联过期需重新关联，不能把旧结论贴到新用例上。

数据空间在同一 dataDir 内跨工作区共享，项目名、环境名不能单独充当全局身份。敏感参数只返回脱敏占位或名称；不使用 `***` 执行，不把密钥、cookies、storageState 或连接口令写进备注与结果。只有原工作流明确支持的私有引用才能用于执行；当前数据空间动态私密参数尚未接入浏览器执行链，遇到此依赖应阻塞，不经聊天传递秘密。

初始化成功即建立持久通道，**不授权生成用例自动入库**。通道仅含工作区、引擎、项目、环境和归档位置，不复制环境参数。环境改动后重新初始化；`disconnect` 加 `engine` / `envId` 停止该通道的新交接，已绑定用例的结果同步仍沿原绑定（停止须逐项 `unbind`）。同地址多个通道不能自动判断归属，须按所选 `envId` 消歧。

## 生成用例后由用户选择入库

生成 UI/API 测试用例后，展示本批用例范围和入库选项；用户尚未明确同意时不得调用 `import`。生成、评审、初始化通道或要求执行测试，都不等于授权入库。用户已明确要求将本批用例录入用例库时，直接在该范围内导入，无需重复询问。选“暂不录入”或尚未选择时，保留原生引用供后续使用。

面向用户输出实际内联选项（不得只描述有按钮）：

[[action:suggest:录入用例库,prompt=将本批生成的测试用例录入所选测试环境所属项目的用例库]]
[[action:suggest:暂不录入,prompt=本批生成的测试用例暂不录入用例库]]

同意后，沿用 `data_space_automation` 的 `import` 名称，传 `engine`、工具实际返回的原生 `assetRef`，并按需传 `envId`、`featureId`、`moduleName`、`featureName`。UI 接受原生 cases ref，API 接受原生 draft ref；既有原生资产引用仍按实际 schema 使用。先核对当前工具能力，缺少引用读取能力或参数时明确阻塞，不伪造 ref、不把任意 JSON 当作受支持输入。

项目以所选 `envId` 所属的 `systemId` 为准，不按同名项目猜测。显式 `featureId` 优先；未指定时沿用既有通道 `featureId`，并核对属于同一项目。无已指定目录时，默认定位“测试用例 → UI用例/API用例”，自定义名称使用 `moduleName` / `featureName`。目录不存在则自动建立，存在则复用；保存并跟随真实目录 ID，用户重命名后继续使用原 ID，不能因默认名称消失而重建原目录。环境或目录被删除、改属或不唯一时明确阻塞，不静默跨项目或重建。

多功能资产先用 `inspect` 取得原生 `moduleId` / `featureId`，传 `featureMappings: [{nativeModuleId,nativeFeatureId,featureId}]` 显式对应数据空间功能 ID；二元 ID 配对，不按名称猜测。单个 `featureId` 是整批默认目标，逐功能映射优先。无明确映射的用例进入默认目录并标记“待归类”，不能把入库成功当成功能归类完成。API 未提供原生功能 ID 时不推测。

`archive-status` 用相同 `engine` / `assetRef` / `envId` 只读核对归档，可附本次预期映射。回执 `counts` 的 `new/existing/pending/stale` 合计为 `total`；`unclassified` 是独立维度，不重复相加。`classificationComplete` 单独表示归类完成；`ok` 不证明无待入库项。`items` 最多 100 项，截断时不可声称已逐项展示全量。旧行没有归类元数据时按未确认归类处理。映射变更、目录删除/跨项目移动或人工移目录均须核对，重试不迁移历史。

此处 `import` 只录入草稿用例，**不创建自动化绑定、不执行测试、不生成执行结果**；绑定仍需独立 `bind`，草稿未冻结前 `bind` 会被拒绝。0.13.0 起宿主实现显式入库，0.14.0 增加映射和归档查询。生成与执行事件不再隐式入库。宿主未重启到该版本时，按旧行为归档的能力可能仍存在，先核对工具 schema 再声明。

## 按来源选择唯一写入路径

| 输入／意图                                       | 操作与边界                                                                                                                                                                      |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户已同意录入的 UI/API 原生用例                 | 生成后先提供入库选项；已获本批授权才显式调用 `import`，传 `engine` / 原生 `assetRef` 及所选环境、目录信息。UI cases、API draft 无需为了入库先形成获批资产；入库不绑定、不执行。 |
| 已有 UI/API 原生批次                             | 查询原工作流证据；用 `data_space_automation` 的 `sync`，传 `engine` 和原 `runRef`。不要再用普通登记重复写一次。                                                                 |
| 关联自动化资产                                   | `inspect` 读取资产后，`bind` 传 `caseId`、`engine`、`assetRef`、`nativeCaseId`、`envId`。UI 引用为真实 `{path,sha256}`，API 为原生资产摘要；绑定由宿主生成版本指纹。            |
| 执行已关联用例                                   | `route` 传 `caseId`，读取返回的全部 `scope.nativeCaseIds`，核对整个资产的执行范围，再调用返回的原工具及参数。按需加载 UI/API 阶段 Skill，台账“已评审”不代替原批准、诊断或预检。 |
| 无原生批次的已观察结果                           | 仅在用户要求登记时使用 `data_space_record_result`；按项目、环境和实际批次分组，每个用例一条。只传公开 schema 支持的字段和结论，不伪造 `source=automation`。                     |
| 无受支持原生引用的人工用例、草稿或无法匹配的数据 | 结构化列为未入库项，说明缺口。不创建占位用例、环境或成功记录；尚不承诺任意人工用例 JSON 可直接入库。                                                                            |

原生用例导入为草稿；同一来源修订、环境和原生用例的重复导入应复用已有行，不覆盖人工编辑，不因目录重命名重复创建。完整步骤、断言和来源以原生引用为准，台账字段受长度上限约束。API draft 入库不代表冻结或评审批准；UI cases 入库不代表 candidate、设计批准或诊断完成。后续自动化关联与执行仍走原工作流门禁。

原生执行完成后宿主自动同步，宿主重启或插件实际重新加载可补同步（设置开关不是服务端重载）。取消或通知丢失时查询原批次，再按原引用 `sync`；同步不重新执行业务。使用 `sync-status` 和原 `engine/runRef` 只读查询逐项对账；`sync` 的回执采用相同口径。`counts.new/existing/pending/unmatched/stale/failed` 互斥，计量单位为用例关联（同一原生用例可有多条显式台账绑定），`nativeCaseCount` 单独列原生用例数。仅 `complete=true` 表示本批全部原生用例的当前关联已确认同步，不代表测试通过或独立报告获批。`pending` 可按原引用 `sync`；`unmatched` 须先完成必要的入库/绑定，`stale/failed` 先核对关联或环境，保留历史。回执逐项最多100条，截断时全量计数仍保留。

核对 `imported`、`duplicate`、`errors`、`unmatched`：`ok=true` 且导入数为 0 不证明目标用例已入库；部分失败逐项保留。原生同步按工作区、引擎、run 和台账用例去重，子集重跑不补写未选中的用例。

普通登记是追加流水，**没有幂等请求键**；返回不明先核对执行结果页，不盲目重发。任务名相同不会合并任务。公开 schema 当前只接受“通过／失败／阻塞”；跳过、取消、未执行、不稳定、未知保留在交付中，不改名挤入接口。人工／AI 登记没有原生证据核验和版本比较写入保证。

## 结构化结果输出

需要整理、同步或回写结果时，读取 [结果交付约定](references/result-output.md)，按一次真实原生 run 或一次人工登记批次输出 JSON；纯用例／环境查询可直接简答。该 JSON 是交付格式，不是新工具参数或 `runs.json` 的文件格式。批次引用、用例结果、同步回执、证据完整性与报告评审分别表达，未知值保留 `null` 和具体原因。

结构化交付可用 [离线一致性校验器](scripts/validate-result.mjs) 检查，调用方法见结果约定末节；校验通过不代替原生证据或独立评审。

交付前核对：范围是否完整；用例／环境是否唯一；结果是否来自本次证据；状态及统计是否保留全部分母；写入回执是否逐项核对。失败原因只写证据支持的事实，推测明确标注。原始失败、父批次及过期结果保留，不用新成功覆盖历史。

维护与接入见 [数据空间接入说明](../../../docs/data-space-integration.md)。
