# 数据空间测试数据规范

数据空间保存用例台账和执行流水；UI/API 原工作流持有资产、批准及执行证据。本 Skill 规范两者交接和 Agent 输出，复用现有工具，不创建另一份结果库、runner 或批准路径。只读整理不自动绑定、执行或回写；用户已要求回写时在该范围内完成，无需逐条重复确认。

## 先定位，后交接

1. 用 `data_space_cases` 按项目和范围查询，执行或评审前读取 `detail=card` 的步骤及预期。内部 `caseId` 优先；只有编号时核对项目及唯一性，不能按标题猜 ID。`get` 的编号查找不按 project 过滤，重号时必须取得真实 ID，不能把同时传入 project 当成消歧。查询截断时缩小范围分批取全；无法取全则标明部分范围，不把前 100 条当全量。
2. 用 `data_space_env` 在所属项目内定位环境，核对实际地址、租户等非敏感条件。默认环境不等于本次执行环境。同名或缺失时保留缺口；绑定必须取得真实 `envId`，普通登记仅在项目内唯一匹配时使用名称。查询未返回 ID 时不得编造或读取私有存储补齐，使用已有明确引用或请用户在数据空间选择。
3. 保留本次取得的 `revision`、用例引用和原生资产／批次引用。聊天锚点只帮助定位，不是版本锁或结果证据。写前发现用例已变更，先核对对应测试版本；原生关联过期需重新关联，不能把旧结论贴到新用例上。

数据空间在同一 dataDir 内跨工作区共享，项目名、环境名不能单独充当全局身份。敏感参数只返回脱敏占位或名称；不使用 `***` 执行，不把密钥、cookies、storageState 或连接口令写进备注与结果。执行凭据沿用原工作流的私有引用。

## 按来源选择唯一写入路径

| 输入／意图                         | 操作与边界                                                                                                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 已有 UI/API 原生批次               | 查询原工作流证据；用 `data_space_automation` 的 `sync`，传 `engine` 和原 `runRef`。不要再用普通登记重复写一次。                                                                 |
| 关联自动化资产                     | `inspect` 读取资产后，`bind` 传 `caseId`、`engine`、`assetRef`、`nativeCaseId`、`envId`。UI 引用为真实 `{path,sha256}`，API 为原生资产摘要；绑定由宿主生成版本指纹。            |
| 执行已关联用例                     | `route` 传 `caseId`，读取返回的全部 `scope.nativeCaseIds`，核对整个资产的执行范围，再调用返回的原工具及参数。按需加载 UI/API 阶段 Skill，台账“已评审”不代替原批准、诊断或预检。 |
| 无原生批次的已观察结果             | 仅在用户要求登记时使用 `data_space_record_result`；按项目、环境和实际批次分组，每个用例一条。只传公开 schema 支持的字段和结论，不伪造 `source=automation`。                     |
| 草稿、推测、未观察或无法匹配的数据 | 结构化列为未入库项，说明缺口。不创建占位用例、环境或成功记录；当前查询工具不支持编辑用例／环境。                                                                                |

原生执行完成后宿主自动同步，重载可补同步。取消或通知丢失时查询原批次，再按原引用 `sync`；同步不重新执行业务。核对 `imported`、`duplicate`、`errors`、`unmatched`：`ok=true` 且导入数为 0 不证明目标用例已入库；部分失败逐项保留。原生同步按工作区、引擎、run 和台账用例去重，子集重跑不补写未选中的用例。

普通登记是追加流水，**没有幂等请求键**；返回不明先核对执行结果页，不盲目重发。任务名相同不会合并任务。公开 schema 当前只接受“通过／失败／阻塞”；跳过、取消、未执行、不稳定、未知保留在交付中，不改名挤入接口。人工／AI 登记没有原生证据核验和版本比较写入保证。

## 结构化结果输出

需要整理、同步或回写结果时，读取 [结果交付约定](references/result-output.md)，按一次真实原生 run 或一次人工登记批次输出 JSON；纯用例／环境查询可直接简答。该 JSON 是交付格式，不是新工具参数或 `runs.json` 的文件格式。批次引用、用例结果、同步回执、证据完整性与报告评审分别表达，未知值保留 `null` 和具体原因。

交付前核对：范围是否完整；用例／环境是否唯一；结果是否来自本次证据；状态及统计是否保留全部分母；写入回执是否逐项核对。失败原因只写证据支持的事实，推测明确标注。原始失败、父批次及过期结果保留，不用新成功覆盖历史。

维护与接入见 [数据空间接入说明](../../../docs/data-space-integration.md)。
