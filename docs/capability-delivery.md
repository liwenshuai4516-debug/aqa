# 新能力接入与交付

### 新能力的管理入口与快捷调用（交付必做）

新增或扩展面向 Agent 的工具、测试能力或工作流时，同一任务内必须自动补齐加载登记、管理入口和 `/` 快捷发现，不得以“仓库里有 SKILL.md”或“SDK 隔离发现通过”代替实际应用接入：

1. **定位实际运行配置**：核对当前引擎、工作区、agentDir 和 dataDir。项目 `.pi/skills/` 只覆盖该项目；应用切换工作区仍需可用的能力，必须登记到该应用专用 agent 配置。保留原有包、扩展、技能和禁用选择，不读取认证文件、不自动信任其他项目。
2. **技能与快捷入口一起完成**：维护唯一技能名、准确描述、原实现引用及必要依赖；在当前应用的“设置 → 技能”可见且可启停。输入 `/关键词`（例如 `/api`、`/ui`）应显示 `/skill:<name>`，点击或 Tab 可补全；禁用后菜单消失，重载后禁用状态保留，重新启用可恢复。优先复用现有技能菜单，不另造绕过原工具门禁的命令。
3. **插件能力同步登记**：若能力依赖宿主插件，补齐 manifest 名称、icon/iconSvg、版本与最小权限，安装/链接到实际 dataDir 的插件目录，在“设置 → 插件”可见、可启停和重新扫描；注册的工具还应出现在工具管理页。仅登记 SDK package/extension 或技能路径不能替代宿主插件安装。无插件实现的普通技能不创建空壳插件；不因内部接入擅自发布社区市场。
4. **提供可重复的接入方式**：新增/更新明确的登记脚本或安装入口，支持显式应用目录；重复执行不得丢配置，遇到其他安装或本地修改不得覆盖。API 使用 `npm run api-testing:enable -- --agent-dir <应用 agent 目录> --data-dir <应用 data 目录>`，UI 沿用 `ui-testing:enable`。依赖安装、应用重载和插件扫描必须纳入本次交付，不能只留下未执行命令。
5. **以界面行为验收**：使用隔离 dataDir/agentDir 先复现缺失，再验证技能页、适用的插件/工具页、`/` 候选、补全、启停及重载持久性，保留证据。实际应用完成登记后核对结果；若旧会话需 `/reload` 或重新扫描才刷新，明确说明当前状态，不宣称它已热更新。此项验收不要求付费模型或真实业务写入。

详细接入与证据见 [API 管理入口验收](api-testing-visibility.md)。
