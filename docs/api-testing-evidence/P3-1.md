# P3-1：仅限 fixture 的宿主定时执行

2026-10-21；前置 P2-2 `4e73b8eadec903c4eae27dae2b66c1cecc192493`。插件 0.3.0，SDK 0.1.3。只支持宿主固定项目、匿名 HTTP loopback fixture 的毫秒间隔。没有启用用户真实环境无人值守任务，也未读取或复制个人凭据。

宿主提供独立 `PluginApiScheduleHost`，与临时聊天调用身份分离；工具建立计划仍经过原有会话、计划/委派及工具权限门禁。固定 assetRef/环境、授权到期时间、本地时区，人工同版本通过后才可建计划。真实目标、凭据参数和跨项目计划拒绝。最多五条启用计划、授权不超过七天、间隔至少 60 秒；本轮仅为已授权工程 fixture 验证提供能力。

业务定义先 temp+rename 保存，宿主声明要求严格保存，失败不启用。原有兼容路径仍保留。宿主回调给出预定 scheduledAt 与实际 firedAt；修复了旧 cron 到点时再次求“下一分钟”导致本次漏触发的问题，先用单测复现再修改，保留失败日志。远期分片没有删除。

每次触发先保存 projectId + scheduleId + revision + dueAtUTC 账本，再调用同一 asset_run/MCP/Newman 入口。重复不再请求；重叠和超过 30 秒的迟到跳过且记原因；不补跑。项目互斥及 unknown 写入继续由既有执行器强制。运行中每 50ms 复核宿主权限、授权到期和时区；撤销取消该次信号，保留 unknown 结果和 run 引用。异常不是自动重试依据。

后台 Stop 持久暂停业务定义，清理宿主声明，重启不复活；正常反激活仅停表并移除后台条目，保留声明，防止宿主兜底 Stop 误当用户停止。恢复前校验声明一致性、时区/授权与未完成 run/claim；不抢占残留所有权、不续跑未知请求。故障后需操作人员核对，服务必须持续运行。
