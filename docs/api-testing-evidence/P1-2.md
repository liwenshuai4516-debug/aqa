# P1-2：确定性检查与有界独立评审

日期 2026-10-21；依据[实施计划](../api-testing-implementation-plan.md) P1-2，前置 [P1-1](P1-1.md)。**控制逻辑工程验收通过；实际模型语义评审尚未执行，不能计作 P1-4 通过。** 没有业务请求或个人凭据访问。

[评审模块](../../plugins/api-testing/review.mjs)导出 `inspectDraft` 和 `reviewDraft`，供后续受控工作流组合。`inspectDraft` 绑定项目和文件真实路径，核对全部冻结文件/hash/compiler，再从净化来源重解析、重编译，逐字比较实际集合与用例。即使修改脚本并重算 manifest，也会拒绝与固定模板不一致的集合。

`reviewDraft` 接受 `complete = host.llm.complete`，每次是宿主已有的独立无工具补全上下文。按用例分批，只发送对应操作、声明式请求/断言、规则与未覆盖项；每批上限 7500 字，超限阻塞而不静默截断。模型回执必须符合严格 JSON schema、回显实际 artifact hash，问题必须引用当前 case。pass 必须无问题；缺事实返回 blocked，不补造规则。审批返回值同时绑定集合字节 hash 与包内内容 hash，尚不授予执行权限。

最多 3 轮/3 次模型调用/90 秒，逐次记录调用、轮次、用量和结果；缺 usage 为 unknown。连续两轮内容无改进停止；修正回调返回新草稿路径，保留原路径与原问题，不能通过递归清零调用账本。非法/截断/错 hash 输出计入轮次；模型不可用、超时、取消和修正失败有限退出。取消/超时后不接受迟到批准，不重新发送接口请求。

现有宿主 `host.llm.complete` 没有 AbortSignal 参数，其超时可能先返回而底层模型调用仍在结束过程中；本模块不会取消模型供应商已发生的消耗，也不承诺“超时已终止远端模型”。会保留未知用量并停止后续调用。P1-4 实际模型验收需确认可用的专用配置/凭据引用，不默认读取个人模型配置。

## 本轮证据

[测试入口](../../tests/api-testing-review-test.mjs)使用真实 parser/compiler 和**明确标记的模型替身**。替身覆盖评审回执/控制分支，不能证明实际模型能识别语义缺陷。最终[摘要](P1-2-summary.json)：已设计/执行 11 项，11 通过、0 SKIP：

- 正常包重编译与精确批准绑定；有意返回 fixture 数据问题后修正新包通过，首次问题保留。
- 连续无改进停止；脚本篡改（即使重写 hash）在模型前拒绝。
- 缺业务事实阻塞；非法、截断及错 hash 输出不批准，计入调用次数。
- 缺/不可用模型有限退出；修正共享调用上限；取消后无迟到批准。
- 总预算不足不启动调用；已经开始的挂起模型在总体时限退出，不自动重试。
