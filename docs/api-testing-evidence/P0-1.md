## 最小验证适配

[测试入口](../../tests/api-testing-p0-test.mjs)直接复用仓库 `McpClient`。原生对照使用未修改的 npm MCP server；只把 Postman API 指向本机 fixture 服务，以合成 key 验证集合获取和上传路径，不访问实际 Postman 云。这是替代外部 API 的对照环境，**没有 mock MCP 回包或 Newman 结果**。

[本地入口](../../tests/fixtures/api-testing-p0/local-runner.mjs)使用真实 MCP SDK，直接调用固定版本的上游 `executeCollection`。该入口只读取启动目录中的一个手写集合，单进程单次执行，无模型可选路径/目标，不经过上游 `fetchCollection` / `reportTelemetryAsync`。适配文件只有此入口及[诊断网络钩子](../../tests/fixtures/api-testing-p0/network-audit.cjs)；全部属于测试验证代码。

结构化结果在 MCP `structuredContent` 返回，并写入 `result.json`；执行前写入 run 身份。只投影 fixture 必需的请求路径、状态、`ok` 字段、断言与错误码，不序列化原始 Newman summary、header、token 或 body。合成敏感值在失败断言错误消息中替换。这证明本样例的证据保留/净化能力，**尚非适用于任意业务数据的通用脱敏器**。返回成功、断言通过、执行状态分开记录，零断言为 blocked。

取消与总时限由测试编排器调用桥的 AbortSignal/超时，再显式 `close()` 专属 runner。实测仅取消 RPC 时 Newman 仍存活；关闭后 PID 消失，另一 runner 仍存活；没有重发请求。部分结果保留 unknown，不声称写入已回滚或补偿已完成。这里未实现产品级生命周期门禁。

## 接入决策与停止边界

仅允许下一任务 P0-2 使用手工审定的自包含 fixture 验证宿主门禁。接入真实目标前仍须证明文件根边界、重定向后的目标约束、网络出口和进程生命周期隔离，并设计适合实际契约的净化证据；本报告不授予执行权限。

当前未触发“改 Newman 内部/重做 HTTP 引擎/强制上传/不能保留关键证据/不能终止本 run”的候选淘汰条件。本地入口成功绕开云依赖且复用未修改的上游 executor；后续若隔离只能靠扩大无关上游修改或自研沙箱实现，应停止该候选产品化并评估另一成熟 MCP。未建设发行、fork 升级平台、插件、技能、资产管理或定时执行。
