# UI 测试链路增强与精简实施计划

日期：2026-10-23。范围：当前 Pi Agent SDK UI 测试工作流、Playwright MCP、数据空间及 macOS arm64 Electron 接入。经设计自审修订：区分最小闭环、提效和可选试点，以真实依赖放行。

**本文件是待实施计划，不是功能完成或验收通过声明。** 本轮仅整理计划书；历史测试只作为回归参考。执行本计划时逐项更新状态、证据和阻塞原因，不因计划已编写就将实施任务标为完成。

## 1. 目标与范围

目标是降低首次生成、已有资产回归和失败续跑的成本，同时保持功能覆盖、断言质量、执行权限及证据可追溯性。

成功应同时满足：

1. 初始化错误在浏览器业务动作前明确暴露，阻塞不会冒充产品失败或最终完成。
2. 新页面按功能逐步探索、核验定位并生成候选；已有资产回归、旧结果分析无需重新探索。
3. Agent 处理功能理解、场景选择和失败解释；程序处理引用传递、确定性检查、阶段交接和数据归档。
4. 用例及结果准确归属项目、环境、功能和资产版本；同一操作的重试按引用去重，明确发起的新回归仍产生新批次；业务写入结果未知时停止自动重放。
5. 提速有同范围对照数据，不能以减少用例、断言、清理或评审作为收益。
6. 在 Electron 实际界面及其共享后端验收，不以独立网页或隔离 SDK 测试代替桌面接入。

本期复用既有原生 runner 和批准路径，优先兼容原资产格式；确有缺口时才扩展契约并验证旧资产。不另建测试平台、定位器数据库、结果库或通用编排引擎。Windows/Linux、其他浏览器、真实生产写入、社区发布不在本计划验收范围内。

真实模型评审和真实业务环境测试在已有授权及可用环境范围内执行，不重复索取已提供的授权；模型可用性、凭据和测试数据在实施时核实，不把历史额度状态当成永久事实。控制夹具可用于确定性回归，但不能替代真实模型遵循度验收。相关条件未满足时，保留对应阻塞项，不宣称完整端到端验收完成。

- **M1 最小闭环**：环境准备→功能探索→设计/现行评审和诊断→正式执行→结果评审→归档对账，在 Electron 验证一条有来源的完整链路及关键阻塞路径。只有合成目标证据时仅记工程链路通过；真实模型及目标条件缺失时，相关验收仍阻塞。M1 不代表整份计划或提效目标完成。
- **M2 提效交付**：在 M1 基础上减少确定性交接与重复读取，并验证诊断/分析优化；完成第 5 节对照及必需回归，才关闭本计划的最终交付。
- **U08 可选试点**：不阻挡 M1、M2。不开展时记录“未启动，保留串行”，不能记为试点通过；开展后独立验收，不能沿用 M2 结果证明并行安全。

前置失败时停止依赖它的后续节点并保留原因，不影响无依赖关系的独立工作。验收不适用须说明实际路径或能力不涉及的依据，不能用“不适用”回避范围内必需检查。

## 4. 分项工作与验收标准

### U00：确认维护源与建立基线

工作：定位原生工作流可维护源码、包版本、分发摘要、应用登记与相关依赖；冻结同一组合成页面、输入数据、角色、部署版本和测试范围。复用现有集成夹具，不为本次计时另建平台。

验收：

- A00-1：记录宿主提交号、工作区已有改动及采用的公开契约；需修改原生包时，能追溯到维护源码并重建分发包。源码不可得只阻塞相应原生修改及依赖它的验收，不阻止独立的宿主修复或 Skill 设计；不能直接补丁安装目录冒充交付。
- A00-2：固定三类基准任务：首次发现生成、已有资产回归、已有失败批次分析/重跑；另设只读查看路径确认零浏览器启动。
- A00-3：记录阶段耗时、工具调用、浏览器启动、导航/快照、静态检查、目录扫描、模型评审次数和归档量；标明冷启动与复用条件。
- A00-4：预登记业务功能清单、预期断言、允许副作用、清理规则和成功/失败夹具；不得依靠优化后的实际结果反过来调整基线。
- A00-5：登记现有失败与环境限制，历史通过不得记为本轮执行。清理仅预览，保留所有失败证据。
- A00-6：核对原生诊断所需正常/错误应用副本、不同 origin、角色及数据隔离是否可得；合成页面的诊断不能批准无关业务页面。针对 OperationContract，登记真实测试环境与预期依据；若无法满足正式执行门禁，允许保留探索/设计成果，但正式执行及最终业务验收继续阻塞。

### U01：统一完成、失败和阻塞语义

工作：先用最小测试复现 partial 报告交付后任务完成的问题，再修改原生交接与宿主展示。保留已有产物；补齐修复后续跑路径，不换任务 ID 逃避阻塞。

验收：

- A01-1：执行前录制不完整、设计未批准、运行未就绪或前置证据缺失时，依赖节点保持待执行/阻塞，正式 runner 调用数为 0。执行后才发现结果证据缺失时，保留真实 run 和已发生的动作，阻塞依赖完整证据的最终交付，不能倒写为“从未执行”。
- A01-2：partial 报告可保存和查看，最终交付节点不完成，展示具体缺口及可恢复入口。
- A01-3：证据完整、评审合格的失败测试报告可以正常完成交付；业务测试失败与工作流执行故障分别表达。
- A01-4：修复缺口后显式续跑，沿用原任务范围、已有证据及评审预算；历史 partial、原失败和父批次不覆盖。
- A01-5：检查任务状态、看板、桌面展示、数据空间的含义一致；新状态若需通信协议字段，仅在 server/protocol.ts 定义。

### U02：统一环境准备

工作：在现有入口按任务模式准备环境。浏览器录制核对运行时、配置和 seed；已有资产回归核对资产及本次运行条件；仅源码设计、查看或分析旧批次不要求新 seed、登录或创建通道。配置检查与浏览器访问分层，按需复用录制/执行 context，形成可追踪回执，不为“预检”默认多启动一个浏览器。

验收：

- A02-1：数据空间闭环模式唯一匹配返回真实项目/环境 ID；无匹配、多匹配、跨项目或 URL 不符时阻塞该闭环，不自动选择默认项。数据空间未安装/停用时不承诺归档；只执行已授权的原生独立任务可沿原门禁运行，不能伪造通道或环境 ID。
- A02-2：浏览器录制路径用独立 Playwright 安装、自定义 testDir、相对 baseURL 及相对 seed 复验原故障。该路径 seed 未找到/匹配多项、浏览器 project 不存在、依赖不兼容时，在业务动作前阻塞；已执行证据只能算回归，不能将已修复问题重复列为本轮待开发。已有资产回归不强制新增录制 seed。
- A02-3：动态参数未过期时复用；过期按原权限刷新并保留有效期和来源；刷新失败不继续使用过期值、不悄悄退回其他环境。
- A02-4：只读查询不触发环境脚本或业务请求；刷新涉及的网络/写入在执行侧受限，计划、只读、禁用状态不能绕过。
- A02-5：秘密只以受控私有引用交给执行层，不进入模型上下文、工具普通输出、用例、报告或归档；使用合成秘密做泄露断言。
- A02-6：配置、网络、身份/角色和数据分别有“就绪/未就绪/未知”及依据；未检查不能记就绪。身份或数据不满足用例前置条件时记初始化阻塞；用例本就测试未登录、无权限或错误数据时按其预期执行，保留真实产品断言结果。
- A02-7：运行前核验当前条件；不能把上次已登录或旧准备回执当永久有效证明。

### U03：减少 Agent 手工串联

工作：沿用现有 modes 和 checkpoint。由程序提供当前任务的最小必要引用，并在产物已通过校验后执行确定性交接；有歧义、门禁失败或未知副作用时停止。new 到 execute 的授权与任务边界保留，可关联同一用户目标展示。

验收：

- A03-1：新建只进入所需发现/设计路径；已有资产执行不录制；analyze 不启动浏览器；view 的工具路径不额外发起评审/分析模型调用，不产生新测试或归因结论。用户对话本身的模型响应单列，不承诺零模型响应。
- A03-2：在已有契约允许的环节，Agent 无需从聊天复制 task_ref/run_ref 等引用；版本冲突重新读取最新状态，不覆盖旧任务。
- A03-3：重复事件、取消、断连和重启不会重复交接或重复启动；未知写入不自动重放。
- A03-4：只加载当前所需技能；入口不复制阶段正文、不将所有技能全文预载。
- A03-5：设计批准不自动授予执行业务权限；用户已要求“生成并执行”且范围明确时，沿用该授权完成原生任务衔接，不重复询问。执行范围包含整个资产时准确显示，超出已授权范围的部分不执行。入库、绑定及同步各按 U00 核定的独立规则办理，不从环境匹配推导授权。

### U04：消除重复扫描与读取

工作：先做单次请求内的读取复用；只有测量证明全量目录或历史同步是主要开销，才选择目标查询、增量目录或已同步索引中的必要方案，不要求全部实现。建立明确失效条件，保留恢复/核对入口；执行前仍由权威门禁核验。

验收：

- A04-1：有测试通道的一次同步，同一原生 run 的完整读取不重复；去重不丢失父批次、全部终态、证据完整性或评审状态。
- A04-2：同一请求内的同目标查询不重复全量扫描。若 U00 证实跨请求全量扫描为瓶颈，再验收增量方案；增加/删除/篡改文件后，执行门禁仍识别失效，缓存不能继续授予批准。
- A04-3：重复启动补同步不重复写入。若历史完整读取为已确认瓶颈，再验收“仅对新增或需核对批次完整处理”的索引方案；保留轻量核对，不声称启动零扫描。未实现索引时明确成本与推迟理由，不声明增量优化已完成。
- A04-4：一个工作区不可访问时，记录错误，其他独立工作区仍能恢复；单个损坏批次不终止全部补同步。
- A04-5：用小样本与扩大的历史资产集比较读取/扫描次数和耗时；若引入缓存或索引，验证损坏时可安全重建，不能丢原始证据。

### U05：按功能探索并复用定位

工作：在现有 discover-record 中建立页面概览，选择范围内高优先功能，探索其状态、核验定位并形成候选；按功能逐步推进。复用 inventory、helper、fixture 和同一次录制会话，不建新的探索阶段。

验收：

- A05-1：合成页面至少含查询/重置、弹窗或抽屉、标签/展开状态、列表分页、权限隐藏、加载/空/错误状态；全部预登记范围内功能均被发现或明确标注阻塞，不把隐藏功能当不存在。
- A05-2：一个功能的草稿形成不以探索完整个系统为条件；同一录制会话覆盖其必要状态，返回/导航次数可计量。正式候选仍须满足冻结任务范围及现行完整性交接；需要按功能独立交付时预先冻结各自范围，不用拆分掩盖原目标缺口。
- A05-3：功能有稳定 ID、入口、角色、状态、来源和场景；复用已有 inventory 字段。只有确认原契约无法表达的定位证据关联才扩展 schema。
- A05-4：定位器在相应状态验证唯一匹配和可操作性；重复按钮、iframe 或动态列表按实际页面处理。优先角色/标签/稳定测试属性，不把临时 ref 写进可复用脚本。
- A05-5：页面/角色/依赖变化时受影响定位重新核验；不能将旧缓存或源码推测标为本轮浏览器验证。
- A05-6：每条候选可追溯功能→场景→断言→脚本；预期来自需求/声明/明确基线，未知规则留缺口。观察到的实际值不得直接充当正确预期。
- A05-7：正常、异常、边界、权限和数据一致性按适用风险选择；合并重复用例时保留所有原覆盖点及断言，不用减少覆盖换取提速。
- A05-8：范围外功能保留 unexplored；范围内真实缺口继续阻塞相关交接，不能删 gap 获得通过。
- A05-9：在任务开始时记录探索范围、时间/动作预算和完成条件；达到预算后保存功能清单、状态证据及缺口，不无限遍历。复用同版本页面的既有清单，只补本次范围内缺失或变化项；预算耗尽不等于全部发现完成。

### U06：功能归档与可核对回执

工作：将原生功能 ID 与数据空间功能 ID 显式关联；多功能资产按映射分别归档。未知归属进入可追溯的待归类范围，不按同名猜测。展示当前版本和历史版本，沿用既有资产/流水事实源。复用已有 [data-space-testing Skill](../.pi/skills/data-space-testing/SKILL.md) 与结果交付约定，补齐双向交接规范，不再创建同职责 Skill。

验收：

- A06-1：两个项目存在同名功能、同名环境时不串项目；一个资产包含多个功能时，各用例按明确映射归属。
- A06-2：未匹配功能明确待归类；映射更新、功能删除或移动后重新校验，不静默迁移历史结果。
- A06-3：重复 import、重复完成事件、并发 sync 和重启补同步不增重复用例/结果；新修订保留，人工编辑不覆盖。
- A06-4：提供可查询的归档回执，区分新增、已存在、未匹配、过期、失败和仍待同步；回执含项目/环境/资产/run 引用及准确数量，不将 imported=0 解释为同步成功。
- A06-5：同步失败按原引用补同步，不重新执行测试；取消、未知、跳过、未执行、不稳定不挤入通过/失败。
- A06-6：当前版本展示减少重复行干扰，历史证据、父批次与版本仍可查看；先核对现有 UI 能力，不重复实现已有版本筛选。
- A06-7：结构化交付能关联项目、环境、功能、用例修订、原生资产及批次、逐例状态、证据和同步回执；未入库项与原因独立表达。字段复用现有结果交付约定，未知值不伪造；合法样例及缺字段、跨项目、状态/统计矛盾样例均有校验结论。交付格式不直接冒充公开工具入参或底层存储格式。
- A06-8：修改后重新通读 Skill，逐条核对公开工具契约、只读/执行边界、私密数据、幂等及版本规则；记录合规、冗余和场景适配审查结论。删除重复 runner/批准说明，以引用代替重复规则；验证环境查询、生成用例归档、原生结果补同步、人工结果登记及部分失败五类场景。

### U07：复用诊断与简化分析

工作：先在现有规则下复用有效诊断，允许一个合理错误探针覆盖相关多条断言；对同类失败先分组，再逐实例保留证据。成功批次输出程序生成的简洁摘要，完整报告仍按原批准路径。

验收：

- A07-1：复用仅限现行门禁允许且输入指纹一致的诊断证明；核对资产、规则、依赖、配置、目标部署、角色及数据适用条件，未知影响不能猜作一致。变更后的失效规则由原生门禁执行，新的环境与数据预检仍执行；不能只凭脚本 hash 不变复用。
- A07-2：探针覆盖关系完整，每条受要求断言均有合理错误观察证据；不修改业务服务、不放宽断言制造诊断成功。
- A07-3：同类失败能归组，但每个非 passed 实例仍有完整结论及本批次证据关联；一个样本不能替其他实例证明根因。
- A07-4：全通过批次不生成冗长人工解释；统计由冻结计划和原生结果对账产生。未知根因允许如实交付，不编造服务端原因。
- A07-5：保留全部 attempts、首败后通过、数据残留、取消及证据缺口；报告评审不重复执行业务。
- A07-6：风险分级放宽诊断/评审仅输出单独策略提案与对照设计。本轮优化保持现行门禁，不由 Skill 私自跳过；新策略未获明确决定不启用。

### U08：受控并行试点

工作：M2 完成后，只有测得串行浏览器执行为主要瓶颈，且独立 context、独立数据和可靠清理已证明时，才启动本试点。用合成夹具比较串行与受控并行，先复用 Playwright 能力，不引入新的任务调度平台。

验收：

- A08-1：共享状态、依赖顺序、资源争用或清理归属不明确的场景保持串行。
- A08-2：以串行结果为对照，验证执行数量、断言结果、实例证据和数据清理一致；至少 10 次试跑无已观察的数据串扰、孤儿进程或残留，报告样本限制。
- A08-3：取消、超时和单例失败不损坏其他实例证据，未知写入仍阻塞相关恢复；不增加自动重试掩盖不稳定。
- A08-4：收益不足或隔离失败时保留串行并记录原因；若要启用，必须同步原生 schema、执行约束、技能和相关回归，不只在配置里改 workers。

### U09：桌面与全链路交付

工作：按 M1、M2 分别验证 Electron 接入；仅在涉及原生修改时重建其分发包，并重建受影响共享应用。M1 验最小闭环，M2 验全部核心改动及性能，不把桌面问题积压到最后。

验收：

- A09-1：M1 对 U01、U02、U05、U06 及本阶段适用桌面检查逐项留证；M2 对 U01–U07 全部范围内必需验收留证。U08 另行记录未启动/通过/失败，不作为核心交付前置；M1 通过不能将 U09 或本计划整体标完成。
- A09-2：真实 Electron 验证环境准备→功能探索→候选生成→评审/诊断→正式执行→分析/结果评审→数据归档；控制评审与真实模型评审分开记录。合成目标验证工程链路；OperationContract 作为真实目标核验可用性、功能清单、用例与结果归属，范围按已有授权及 U00 冻结记录。真实模型或真实目标条件缺失时，该部分继续阻塞，不能用合成页面冒充原页面已验收。
- A09-3：复验已有资产回归、仅查看、仅分析、失败重跑、证据缺失、进程取消、断连、重启恢复及错误环境；未知副作用不自动重放。
- A09-4：设置页技能/工具/插件可发现、可禁用启用；/ui、/data 可补全，禁用偏好重载后保持；执行侧调用亦受限制。
- A09-5：核对实际应用配置指向新版本，不覆盖个人安装或认证，不中断原服务。隔离桌面验收后，明确实际应用是否需重启/重新扫描及 /reload，不宣称旧进程已刷新。
- A09-6：M1 不以性能优化为放行条件；M2 按第 5 节冻结的指标对照。质量门槛通过且指标达标才能声明“优化达标”；正确性达标但性能未达标分别报告，不修改指标掩盖差距。基础记录不要求先建设独立观测平台。
- A09-7：按项目要求执行格式化、全量 typecheck、相关 Vitest、lint、协议检查、差异检查及集成；插件版本/已跟踪 bundle/技能入口/文档同步。缺失依赖先处理，不把未执行算通过。
- A09-8：仅提交本任务明确差异，推送当前分支并核对远端 SHA；无法核对时明确状态。回滚用 revert，不强推或删除历史。

## 5. 性能与质量对照规则

下表中的正确性是硬门槛，20% 是待基线验证的提效目标，不是未经测量的承诺。U00 固定计量口径并收集基线，在 M2 实施前依据可消除开销占比冻结具体目标；无优化空间的路径保留测量结论，不为达百分比增加抽象。目标冻结后不能因结果不佳悄悄降标。

阶段开销按日志边界测量：框架自身的读取、校验、路由和归档分别计时；模型等待、浏览器执行及人工等待单列，并发区间不重复相减。“编排调用”限定为工作流状态/引用传递/同步等确定性工具调用，不把必要浏览器动作和评审调用纳入可删减项。

| 指标                 | 测量办法                                            | 目标                                                                                  |
| -------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 功能、场景和断言覆盖 | 对照预登记范围及证据映射                            | 既有覆盖点保留 100%；适用新增范围全部有通过/失败/阻塞/未执行归属                      |
| 结果及数据一致性     | 冻结计划、原生报告、台账、流水逐项对账              | 不串项目、不漏选定实例、不重复业务执行；归档最终对账完整                              |
| 初始化错误拦截       | 错误配置/依赖/seed/认证夹具                         | 应阻塞的夹具全部在业务动作前阻塞                                                      |
| 首次生成的机械开销   | 同范围、同起点、同候选终点，统计编排调用与重复导航  | 编排调用减少 20% 为初始目标，U00 后冻结；重复导航不增加                               |
| 已有资产回归开销     | 同资产、同范围、同原生执行终点；浏览器/模型时间单列 | 框架开销减少 20% 为初始目标，U00 后冻结；同时报告绝对耗时和总耗时占比，结果与证据一致 |
| 单次结果同步         | 单次调用中的同 run 完整读取计数                     | 同一 run 不重复完整读取                                                               |
| 查询/补同步扩展性    | 小样本与扩大历史集，分别测量冷/热状态               | 按 U00 确认的瓶颈验收选定方案；没做增量不声称已做，所有方案均保证幂等及权威失效检查   |
| 端到端耗时           | 相同有效覆盖、批准等级和模型配置                    | 分场景报告变化；中位数回退超过 10% 须说明并修正，不能只报告局部收益                   |

M2 每个确定性基准场景至少执行 5 组成对对照，交替前后版本顺序，记录所有样本、中位数及最大值；冷启动与复用样本分开。浏览器、机器负载、依赖和数据固定，失败/取消样本独立列出，不从总记录删掉。该样本量用于工程对照，不宣称统计显著；波动大于所报收益时补样本或报告收益未证实。M1 仅采集必要基线，不等待全部性能试验。

模型耗时和费用单列；有授权后再执行相同模型配置的端到端对照。零模型的脚本基准只能说明机械开销，不证明 Agent 更会理解页面或最终完整任务已提速。

## 7. 交付、证据与恢复

每阶段交付一个简洁记录：任务编号、版本/环境、改动范围、验收编号、已设计/已执行/通过/失败/阻塞/未执行/SKIP 数量、证据引用、剩余风险和下一步。统计口径注明单位，不混用用例数、实例数和检查项数。

复用既有任务看板、原生产物目录及数据空间流水；qa/ui 只是后备默认值，工作区实际配置优先。本计划只登记实施状态，不创建另一份运行事实库。工程回归证据写 tests/scratch 的本次目录；真实业务证据沿项目受控位置保存，大型证据按既有规则保留校验索引。依赖和浏览器缓存共享，失败证据不自动删除。不得将秘密、个人认证或未授权业务内容写入截图、trace、报告和提交；使用合成秘密验证截图/trace 等证据渠道，敏感页面必要时关闭捕获并如实标记证据限制，不靠工具文本脱敏宣称全链路无泄露。

原生包修改从可维护源码重新构建、校验分发摘要并更新锁定依赖；入口 Skill 继续引用原实现。管理页和自动衔接变更按能力交付规则一并验收，桌面仍是优先对象。

前置失败时：保存原始证据→更新当前节点为失败/阻塞→依赖它的下游保持待执行并注明原因→修复原问题→从受影响节点显式续跑。阶段报告不代表最终验收完成。未知业务写入先核对归属和现场，不换任务 ID 重放。

回滚按阶段独立提交，用 revert 恢复代码；新增索引可重建，迁移前保留原始备份。不得删除台账、旧 run、评审或历史失败来实现回滚；若新数据版本不能被旧版读取，先停止相关写入并采用已验证恢复路径。

## 9. 设计自审结论

原方案的方向可保留：复用原工作流、先明确阻塞和证据，再增强探索及数据闭环，不另造平台。原顺序和部分验收不宜直接执行，已作以下修订：

| 原设计问题                                                   | 本次修订                                            |
