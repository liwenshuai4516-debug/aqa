# 原生用例入库、绑定与同步

仅处理入库、功能归类、绑定、执行路由或结果同步时读取；先按入口完成项目/环境定位，工具参数以当前 schema 为准。

## 生成用例后由用户选择入库

生成 UI/API 测试用例后展示本批用例范围；本批尚未明确授权时提供入库选项，不得调用 `import`。生成、评审、初始化通道或要求执行测试，都不等于授权入库。用户已明确要求将本批用例录入用例库时，直接在该范围内导入，无需重复询问。选“暂不录入”或尚未选择时，保留原生引用供后续使用。

🔴 CHECKPOINT：入库前用 `inspect` 核对完整原生用例范围与本批授权。当前 `import` 处理整份 `assetRef`，没有用例子集参数；仅获子集授权或范围无法确认时停止入库，说明未入库项与范围差异，不编造筛选字段，也不把 `featureMappings` 当作用例筛选。已明确授权整批且范围匹配时直接办理，不重复确认。

同意后，沿用 `data_space_automation` 的 `import` 名称，传 `engine`、工具实际返回的原生 `assetRef`，并按需传 `envId`、`featureId`、`moduleName`、`featureName`。UI 接受原生 cases ref，API 接受原生 draft ref；既有原生资产引用仍按实际 schema 使用。先核对当前工具能力，缺少引用读取能力或参数时明确阻塞，不伪造 ref、不把任意 JSON 当作受支持输入。

项目以所选 `envId` 所属的 `systemId` 为准，不按同名项目猜测。显式 `featureId` 优先；未指定时沿用既有通道 `featureId`，并核对属于同一项目。无已指定目录时，默认定位“测试用例 → UI用例/API用例”，自定义名称使用 `moduleName` / `featureName`。目录不存在则自动建立，存在则复用；保存并跟随真实目录 ID，用户重命名后继续使用原 ID，不能因默认名称消失而重建原目录。环境或目录被删除、改属或不唯一时明确阻塞，不静默跨项目或重建。

多功能资产先用 `inspect` 取得原生 `moduleId` / `featureId`，传 `featureMappings: [{nativeModuleId,nativeFeatureId,featureId}]` 显式对应数据空间功能 ID；二元 ID 配对，不按名称猜测。单个 `featureId` 是整批默认目标，逐功能映射优先。无明确映射的用例进入默认目录并标记“待归类”，不能把入库成功当成功能归类完成。API 未提供原生功能 ID 时不推测。

`archive-status` 用相同 `engine` / `assetRef` / `envId` 只读核对归档，可附本次预期映射。回执 `counts` 的 `new/existing/pending/stale` 合计为 `total`；`unclassified` 是独立维度，不重复相加。`classificationComplete` 单独表示归类完成；`ok` 不证明无待入库项。`items` 最多 100 项，截断时不可声称已逐项展示全量。旧行没有归类元数据时按未确认归类处理。映射变更、目录删除/跨项目移动或人工移目录均须核对，重试不迁移历史。

此处 `import` 只录入草稿用例，**不创建自动化绑定、不执行测试、不生成执行结果**；绑定仍需独立 `bind`，草稿未冻结前 `bind` 会被拒绝。0.13.0 起宿主实现显式入库，0.14.0 增加映射和归档查询。生成与执行事件不再隐式入库。宿主未重启到该版本时，按旧行为归档的能力可能仍存在，先核对工具 schema 再声明。

## 按来源选择唯一写入路径

| 输入／意图                                       | 操作与边界                                                                                                                                                                                                                                   |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户已同意录入的 UI/API 原生用例                 | 已获本批授权且整份资产范围匹配时直接调用 `import`，传 `engine` / 原生 `assetRef` 及所选环境、目录信息。UI cases、API draft 无需为了入库先形成获批资产；入库不绑定、不执行。                                                                  |
| 已有 UI/API 原生批次                             | 仅分析／查看时只读原生证据或 `sync-status`；已获同步／回写授权且范围匹配时才用 `sync`，传 `engine` 和原 `runRef`，不重复普通登记。                                                                                                           |
| 关联自动化资产                                   | `inspect` 读取资产后，`bind` 传 `caseId`、`engine`、`assetRef`、`nativeCaseId`、`envId`。UI 引用为真实 `{path,sha256}`，API 为原生资产摘要；绑定由宿主生成版本指纹。                                                                         |
| 执行已关联用例                                   | `route` 传 `caseId`，核对全部 `scope.nativeCaseIds` 是否在本次授权内；超出或范围不明时停止并说明差异，不私改返回参数伪造子集。范围匹配后按需加载 UI/API 阶段 Skill，再沿返回的原工具及参数进入原批准、诊断与预检，台账“已评审”不代替原门禁。 |
| 无原生批次的已观察结果                           | 仅在用户要求登记时使用 `data_space_record_result`；按项目、环境和实际批次分组，每个用例一条。只传公开 schema 支持的字段和结论，不伪造 `source=automation`。                                                                                  |
| 无受支持原生引用的人工用例、草稿或无法匹配的数据 | 结构化列为未入库项，说明缺口。不创建占位用例、环境或成功记录；尚不承诺任意人工用例 JSON 可直接入库。                                                                                                                                         |

原生用例导入为草稿；同一来源修订、环境和原生用例的重复导入应复用已有行，不覆盖人工编辑，不因目录重命名重复创建。完整步骤、断言和来源以原生引用为准，台账字段受长度上限约束。API draft 入库不代表冻结或评审批准；UI cases 入库不代表 candidate、设计批准或诊断完成。后续自动化关联与执行仍走原工作流门禁。

🔴 CHECKPOINT：`sync` 可能写入同一原生 run 的全部当前关联，当前没有台账用例子集参数。调用前用 `sync-status` 核对待写关联是否全部在本次授权内；待写范围超出授权，或逐项回执截断且无法确认全量范围时，不调用 `sync`，保留缺口，不解绑其他用例来绕过范围限制。

原生执行完成后宿主自动同步，宿主重启或插件实际重新加载可补同步（设置开关不是服务端重载）。取消或通知丢失时先查原批次和 `sync-status`；仅在用户已授权同步／回写且范围匹配时按原引用 `sync`，不重放业务。仅分析／查看时保留缺口，不触发补同步、入库或绑定。使用 `sync-status` 和原 `engine/runRef` 只读查询逐项对账；`sync` 的回执采用相同口径。`counts.new/existing/pending/unmatched/stale/failed` 互斥，计量单位为用例关联（同一原生用例可有多条显式台账绑定），`nativeCaseCount` 单独列原生用例数。仅 `complete=true` 表示本批全部原生用例的当前关联已确认同步，不代表测试通过或独立报告获批。获准且范围匹配的 `pending` 可按原引用 `sync`；`unmatched` 仅在已有对应入库／绑定授权时处理，`stale/failed` 先核对关联或环境，保留历史。回执逐项最多100条，截断时全量计数仍保留。

核对 `imported`、`duplicate`、`errors`、`unmatched`：`ok=true` 且导入数为 0 不证明目标用例已入库；部分失败逐项保留。原生同步按工作区、引擎、run 和台账用例去重，子集重跑不补写未选中的用例。

普通登记是追加流水，**没有幂等请求键**；返回不明先核对执行结果页，不盲目重发。任务名相同不会合并任务。公开 schema 当前只接受“通过／失败／阻塞”；跳过、取消、未执行、不稳定、未知保留在交付中，不改名挤入接口。人工／AI 登记没有原生证据核验和版本比较写入保证。
