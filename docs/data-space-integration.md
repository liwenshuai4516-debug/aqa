# 数据空间与 UI/API 自动化接入

结论：可接入，采用“台账关联 + 原工作流执行 + 原生证据投影”。0.8.0 原版不宜直接作为可信执行结果源；本次 0.9.0 修复已复现的数据可靠性缺陷，并完成隔离工程验收。

验收环境：本机 macOS、Node 23.10.0、锁定 Playwright 1.62.1、共享锁定 API 依赖。全部使用临时工作区、dataDir/agentDir、loopback 合成目标及端口 ≥8900；精确停止自建服务，无个人数据和业务环境写入。API 评审与 UI 独立评审响应是**明确标记的控制替身**，批准门禁、诊断、执行器、报告与证据核验均使用原实现；不声称通过实际模型评审。

前期隔离探针已复现写盘失败仍成功、批次元数据丢失、同名环境跨项目、查询脱敏缺失、删除用例后重载丢历史。新增回归先覆盖故障，再验证修复。浏览器首次回归发现新增按钮被窄列遮挡，调整操作列后使用正常点击通过；执行守卫回归发现插件身份原先仅在进入 MCP 时校验，已补调用创建时校验，直接写台账的工具也受计划/委派/目标审查门禁限制。

## 维护与调用

- 实现：`plugins/data-space/{model,runs,durable,automation}.mjs`；界面 `client/modal-automation.mjs`。
- 宿主：`server/test-asset-reader.ts` 只读核验原生文件；UI 复用 `ArtifactStore/reconcileRun`，API 复用已安装插件的 `inspectDraft` 确定性核验。`server/test-execution-notice.ts` 仅发执行引用，通知不代表测试通过。
- `host.testing.inspect/read/list` 需 `tools` 权限，见 `plugin-sdk/README.md`。新增工具使用插件动态登记，不复制宿主工具目录或执行器。
- 技能：`.pi/skills/data-space-testing/SKILL.md`，`/data` 发现，沿用原 UI/API 阶段技能。
- 显式登记：`npm run data-space:enable -- --agent-dir <应用目录> --data-dir <数据目录>`。保留已有设置、禁用选择；不同安装拒绝覆盖。当前项目技能由项目目录加载，应用跨工作区使用需显式登记。
- 回归：`npm run test:data-space:native`、`npm run test:data-space:browser`；后者先通过统一构建检查器保证构建，不并发重建。断言失败保留证据，不 SKIP 或削弱断言。

用例库 → 自动化 → 读取原生资产 → 选择原生 case/项目环境 → 保存关联 → 引入执行对话。草稿明确：**将运行整个原生资产中的用例**，发送前核对全部用例与写入授权。继续原批准、诊断及预检，不把台账“已评审”视为批准，不自动发送。

正常完成引用触发自动同步；重载后补同步已有批次，绝不重放。取消/工具错误可能没有完成引用，应查询原工作流批次历史并手动 `sync`，或重载后恢复；API 不完整取消记录保留为未知。同步失败时修复原因后用原引用重试，不能为了台账而重新执行业务写入。

## 仍需保留的边界

- 单 dataDir 共享台账，无用户/租户级行权限；适合当前可信本机协作，不作为隔离多租户服务部署。
- `ai`/`manual` 是未核验登记，`automation` 才是核验原生结果；`demo` 不计当前结论。历史统计仍可查看原记录分布，通过率排除示例和过期记录；原生执行结果不代表独立报告已获批准。
- 暂未实现自动把任意手工步骤编译为资产；已有原生资产需显式关联。UI 范围缺少明确 base URL 或环境无法匹配时拒绝绑定，不猜测目标。
- 本地 JSON 保留全历史，尚无数据库分页、自动归档或防本机文件管理员篡改的签名机制。大规模历史需另行规划归档；凭据应保持外部引用，文本脱敏不是密钥保险库。
- 工程与合成目标验收已完成；真实业务环境、实际模型效果、Windows/Linux 本轮未执行。原 runner 既有支持边界继续有效。
- 未修改个人插件安装、凭据或运行中服务。已启动旧宿主不会自动拥有新接口；更新后重启宿主、插件重新扫描，已有会话执行 `/reload`。这属于加载新版本，不宣称旧进程已热更新。
