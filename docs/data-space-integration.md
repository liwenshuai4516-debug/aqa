用例库 → 自动化 → 读取原生资产 → 选择原生 case/项目环境 → 保存关联 → 引入执行对话。草稿明确：**将运行整个原生资产中的用例**，发送前核对全部用例与写入授权。继续原批准、诊断及预检，不把台账“已评审”视为批准，不自动发送。

正常完成引用触发自动同步；重载后补同步已有批次，绝不重放。取消/工具错误可能没有完成引用，应查询原工作流批次历史并手动 `sync`，或重载后恢复；API 不完整取消记录保留为未知。同步失败时修复原因后用原引用重试，不能为了台账而重新执行业务写入。

## 仍需保留的边界

- 单 dataDir 共享台账，无用户/租户级行权限；适合当前可信本机协作，不作为隔离多租户服务部署。
- `ai`/`manual` 是未核验登记，`automation` 才是核验原生结果；`demo` 不计当前结论。历史统计仍可查看原记录分布，通过率排除示例和过期记录；原生执行结果不代表独立报告已获批准。
- 暂未实现自动把任意手工步骤编译为资产；已有原生资产需显式关联。UI 范围缺少明确 base URL 或环境无法匹配时拒绝绑定，不猜测目标。
- 本地 JSON 保留全历史，尚无数据库分页、自动归档或防本机文件管理员篡改的签名机制。大规模历史需另行规划归档；凭据应保持外部引用，文本脱敏不是密钥保险库。
- 工程与合成目标验收已完成；真实业务环境、实际模型效果、Windows/Linux 本轮未执行。原 runner 既有支持边界继续有效。
- 未修改个人插件安装、凭据或运行中服务。已启动旧宿主不会自动拥有新接口；更新后重启宿主、插件重新扫描，已有会话执行 `/reload`。这属于加载新版本，不宣称旧进程已热更新。

## 2026-10-23：启动修复与项目测试通道

### 已确认的启动原因与修复

OperationContract 失败发生在录制初始化，原始错误为 `seed test not found`，不是页面功能失败。原 MCP 固定使用安装目录配置（`testDir=qa/ui`），而用户工作区 seed 在 `tests/`；换配置但仍使用宿主 CLI 又会混入两份 Playwright，出现 `Playwright Test did not expect test() to be called here`。原诊断记录位于 `tests/scratch/ui-seed-diagnosis/result.json`。42 条源码候选均未正式执行，不得计为产品失败。

1. **配置与运行时一起修复**：MCP 从当前工作区解析 `@playwright/test` 对应的 CLI，选择工作区唯一 `playwright.config.*`。缺少依赖或多个配置会明确阻塞。无项目配置时才用不加载宿主 Playwright 的后备配置（仅 `qa/ui`，没有业务 baseURL）。独立依赖、`tests/` 目录、相对 URL 必须作为回归场景。
2. **录制前预检**：技能要求用所选 CLI/config 收集唯一 seed，核对 project、testDir、baseURL，然后做浏览器访问及登录检查。相对 seed 绑定守卫保持有效；绝对路径不是修复办法。
3. **错误分层**：配置、依赖、登录、网络问题归初始化阻塞；有业务断言证据才归产品失败。保留旧失败记录，在修复后产生新批次。

### 当时已实现的数据交接（历史记录）

> 本节及下方旧默认目录、自动资产导入行为是上一轮实现和验收记录；本次生成用例入库规则以文末“生成用例后显式选择入库”设计为准。历史测试不证明新设计已实现或通过。

复用四个既有 Data Space 工具；扩展 `data_space_automation`，插件版本 0.11.0。初始化是持久写入，沿用现有计划、只读、委派与禁用守卫；查询不建立通道。没有新 runner、批准路径、数据集库或结果数据库。

- `initialize {engine,targetUrl?,systemId?,envId?,featureId?}`：至少提供一个目标条件，按 HTTP(S) 地址路径边界与明确 ID 匹配；仅唯一结果建立通道。无匹配返回 `missing-environment`，多匹配返回 `ambiguous` 和候选，默认标记不消歧。返回 `configured`、真实 ID、非敏感参数及敏感参数名称；network/authentication 保持 `not-checked`，不能宣称可登录。账号秘密不回传、不写入通道。当前仅环境参数可作为数据输入；旧数据集已移除，不声称支持不存在的数据集能力。

0.16.0 扩展初始化的 `mode`（默认 `new`）及 `discovery`：`analyze`、`view` 或 `new/record + discovery=source` 返回 `not-required`，不选环境、不创建或改写通道、不发目标请求。其他模式仍须唯一匹配；初始化本身仍沿用宿主写操作守卫。`preparation` 分开记录配置、参数及网络/身份/角色/数据状态，未检查为 `unknown`；每次初始化重读当前参数。有效动态值优先于静态值，过期或失败返回 `refresh-required`，不退回同名静态值；显式刷新后须重新初始化。`parameterSources` 提供来源/有效期。秘密或反射秘密的公共值不交给模型；私密执行链尚未接通时 `privateExecution=not-ready`。`configured` 只是匹配成功，不能据此跳过原生运行前预检或宣称浏览器已登录。

- `import {engine,assetRef}`：宿主从原生资产核验 hash、工作区、环境和原生用例。UI 候选与 API 已冻结资产导入草稿，保存步骤／预期摘要与原生引用。自动绑定版本，仍需原工作流的设计评估、诊断与执行许可。完整来源、断言、请求及超过台账字段限额的内容在原生资产保留。
- 原生 `ui_case_design.candidate` 成功及 API review/import/restore 形成资产时，宿主发送仅含引用的事件自动导入。仅保存 cases、尚未形成资产的草稿不自动创建占位台账。事件失败可按原 assetRef 重试 import；技能要求核对回执。
- 正式执行完成后自动导入缺失用例并同步原生结果。宿主进程重启／插件实际重新加载时扫描已有批次补同步；不会重放测试。资产生成事件丢失且未执行时，用 import 补归档；不声称重启会扫描所有未执行候选。
- `disconnect {engine,envId}` 停止当前工作区该通道的新归档；原有显式用例绑定继续同步，停止单条需 `unbind`。同工作区、引擎、相同地址有多个通道时拒绝自动归属，先断开非本次通道。

`<dataDir>/data-space/channels.json` 是版本 1 的通道索引，仅存工作区／引擎／项目／环境／地址／可选功能 ID；不进入页面整库保存，不复制参数或测试结果。`store.json` 继续存台账，新增服务器拥有的 `nativeSource` 幂等来源，普通保存不能伪造它；`runs.json` 继续存证据结果。写入均沿用原子持久化。

默认目录为对应项目的“自动化测试 → UI/API 自动化导入”；初始化传 featureId 可归档到现有功能。导入键为工作区 + 引擎 + 完整资产引用 + 环境 ID + 原生用例 ID。同版本重复不增行，人工编辑不覆盖；不同资产修订保留为不同台账行，不自动合并同名用例。达到现有容量限制整体拒绝导入。项目／环境／功能被删除或改属后阻塞，不自动移动历史证据。

### 自审

- 合规：只归档宿主核验的原生资产与批次，不接受 Agent 自报通过；环境匹配不提供执行授权；私密参数不进入工具输出。

## 生成用例后显式选择入库（已实现，桌面接入待验证）

设计由三个 Skill 先写入，实现随后落入插件 0.13.0：`test-channel.mjs` 负责环境归属与目录复用，`automation.mjs` 去掉资产事件隐式入库并拒绝绑定草稿，`index.mjs` 暴露 `envId` / `featureId` / `moduleName` / `featureName`。上文历史验收不计作本次实测。

- **选择与授权**：生成 UI/API 用例后提供“录入用例库／暂不录入”实际内联选项。未明确同意不得导入；用户已明确要求本批入库则直接办理，不重复询问。初始化、生成、评审或执行请求本身不授权自动导入。旧的 candidate、API review/import/restore 事件自动资产导入规则由显式选择后 `import` 取代。
- **工具与引用**：保留 `data_space_automation` 的 `import` 名称和 `engine` / `assetRef`，扩展接受可核验的 UI cases ref、API draft ref；可选增加 `moduleName` / `featureName` / `envId` / `featureId`。引用必须来自原工具和宿主 reader 支持的格式，不能把内存工作流 ID 或任意 JSON 伪装为原生引用。没有受支持原生引用的人工用例列为未入库项，暂不承诺通用 JSON 导入。
- **项目与目录**：所选 `envId` 决定所属 `systemId`，不按重名项目猜测。显式 `featureId` 优先，未传时保留既有通道 `featureId`，核对归属；没有指定目录时默认“测试用例 → UI用例/API用例”。缺少则自动建、存在则复用，并持久跟随目录 ID；用户重命名后不能按旧默认名称另建目录。环境或目录被删除、改属或歧义时阻塞，不静默搬移。
- **用例与结果分离**：本次 `import` 仅录入草稿用例，不自动绑定、不执行、不生成执行结果。自动化关联沿用独立 `bind`；正式批次结果仍使用既有原生 `sync` 与证据核验，不能把用例入库记为执行成功。UI 设计批准、诊断、正式运行及结果评审、API 冻结评审和预检均保持原门禁。

技能中使用的实际选项为：

```text
[[action:suggest:录入用例库,prompt=将本批生成的测试用例录入所选测试环境所属项目的用例库]]
[[action:suggest:暂不录入,prompt=本批生成的测试用例暂不录入用例库]]
```
