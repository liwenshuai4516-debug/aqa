# api-test-analyze：Darwin 基线评估

日期：2026-10-28。第四项已启动，用户确认复用现有三条问题。**本次诊断分 71.8/100，技能未修改；等待确认后再进入优化。**第三项首轮交付已获确认，第五项尚未开始。

## 主要结论

技能能约束不擅自重发请求、不把 500 或重复失败当作已确认根因、不无限重新分析，并保留首次失败。但“清理状态必须输出五态之一”的表述缺少证据门禁。两份带技能回答在完全没有报告时，把清理状态直接写成 `residuals-unknown`，理由只是“没有清理证据”。

实现中的 `residuals-unknown` 有具体条件：`buildReport` 在 `interrupted` 且套件含写请求时给出此值；没有报告或字段时，只能说状态未知／待核实，不能把自主推断当成宿主 `cleanup`。其他四态也应按原始回执解释，不能重新猜值。此发现来自回答层，尚未证明工具可用时仍会发生同样误报。

还有两个静态契约缺口留待后续：步骤 1 把内存 `report` 的 `runId` 写成可选，但实现要求具体 `runRef` 和 `runId`，省略不会默认取最新运行；回执仅含 summary 与报告／问题路径，不内嵌完整报告。步骤 4 的“无修订时保留失败修订”也不准确：证据缺失或变化、分析正活动、预算耗尽、无未关闭问题等预检查会直接抛错，不创建新修订；尝试建立 pending 后的模型失败才通常落失败修订，未落 manifest 的 pending 还可能成为 interrupted。
