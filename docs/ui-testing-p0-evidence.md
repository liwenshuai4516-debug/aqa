# UI 测试 P0：执行守卫与项目 fixture

执行日期：2026-10-22。范围仅为用户指定的两项 P0，不新增业务测试、模型配置或完整测试资产管理。

## 依据与修复

依据现有计划/委派/目标审查模式、`read-only` 权限及已安装 `pi-ui-testing` 的 operation 实现确定预期。修复前的 11 项复现检查中，7 项失败：UI 正式执行、录制、写资产和 MCP 未被分类拒绝，计划模式 wrapper 仍进入探针执行器；4 项查询检查通过。不是以隐藏工具或模型自觉遵守作为执行限制。

- `server/extension-tool-policy.ts` 区分查询、写资产、浏览器动作和测试执行。查询使用显式名单；解析报告、导出、审查登记等会落盘的操作不归为查询。未知 UI 操作、通用 MCP 和未登记扩展在受限模式保守拒绝。
- `server/extension-tool-gate.ts` 注入 Pi SDK `tool_call`，核对实时会话归属、模式、只读权限及 UI 停用状态，覆盖后注册工具及 `ctx.executeTool()` 嵌套调用。硬模式优先于普通权限，原 wrapper 保留。
- `qa/ui/` 复用实际宿主、`ArtifactStore`、`UiDataScope` 和已有 Chrome/attach 检查，提供临时 dataDir、agentDir、工作区、端口、口令及合成数据。预检检查鉴权、cwd、空消息，不能只凭 health 成功。
- 数据按归属记录创建和清理；正常退出幂等停止自身服务。强杀后由父管道监视器停止服务，保留归属记录，确认 owner/server 均退出后才显式核对并删除临时目录。

维护与复跑命令见 [fixture README](../qa/ui/README.md)。本轮未改工具 Schema、个人安装或个人凭据。

## 未执行与剩余边界

- 未执行外部业务登录/角色、业务录制、独立模型评审、正式业务回归及 Windows/Linux 验收；本项目“身份”仅指口令、clientId 和工作区核对。
- 守卫覆盖 Pi SDK 工具执行管线，不是 OS/网络沙箱。可信 Node 扩展直接调用 IO、非 Pi 引擎仍按各自边界约束；MCP 查询暂未逐个认证，受限模式保守拒绝。
- fixture 强杀无法执行 teardown，必须保留并核对归属记录；不得把目录暂留当作已清理，或按端口/进程名杀无关服务。
- 未自动重启用户桌面服务。更新代码须由运行时加载后才能生效；UI 包升级时应核对 operation 契约、更新分类并执行本页回归。
