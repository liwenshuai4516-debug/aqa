## 主要结论

现有技能能约束不放宽断言、不把导入通过标签当批准、不无限重评，但混合了内部模型结论与公共工具回执。公共 `review` 成功返回 `phase: approved`，不是顶层 `verdict: pass`；`pass/revise/blocked` 属于内部 `reviewDraft` 和冻结评审记录。三份带技能回答均继续使用了“宿主返回／签发 pass”措辞，可能导致无法正确识别公共成功回执。

正文“blocked 的 reason 仅”列出的七项不完整：实际公共路径还有 `missing-business-facts`、`MODEL_TIMEOUT`、`CANCELED`；工作流还可能直接抛状态或预算错误，并非都返回 `blocked`。不能把真实原始原因当作未登记值丢弃、替换或补造。内部带修订回调的函数另有其他原因，但当前公共工作流固定 `maxRounds: 1`、不传修订回调，不能把所有内部原因都声称为公共常见结果。

预算也需分清单位：每工作流累计最多三次**模型调用**，不是三个 review action 的固定额度；一次 review 可能消耗多次模型调用。180 秒从 prepare 开始，每次内部 review 整体至多 90 秒，单个模型调用至多 30 秒。无历史回执时不估算剩余预算；停滞判断依据同一 `suiteHash` 连续三次评审相同（连续两轮无变化），不是仅凭“上次没过”认定触发。
