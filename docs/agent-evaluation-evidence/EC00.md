## M1 数据与操作冻结

schemaVersion 为整数 1。字段及状态沿方案 §5；不新增 Trial。服务端生成 UUID，版本从 1 递增；用户传入新对象 ID/owner/创建时间无效。所有引用包含对象种类、ID、revision 与授权域；授权域由可信宿主上下文给出 `principalId/workspaceId`，会话选区另含 sessionId 与消息起止 ID。项目引用到 EC09 才开放。没有可验证 principal/选区权限时拒绝，不回退全局最近会话。

EC01 实现 contracts/targets/attempts/evidence/snapshots/evaluations/reviews 存储契约；EC02–EC04 才分别接入采集、评分和人工入口。尚无消费者的扩展点不提前注册。跨端类型只放 `server/protocol.ts`，插件运行校验放 `plugins/agent-evaluation/schema.mjs`，不可在 web 定义第二份协议。

- TaskContract：§5.1 必需字段；scope 固定 `source, sessionId, startMessageId, endMessageId, boundaryPrecision, childPolicy`。精度为 exact/selection-snapshot；childPolicy 为 exclude/explicit，explicit 另含 childSessionIds，无法确认关联不自动纳入。proposed 条件不能 required=true。允许 conditions 为空作效率诊断。
- ExecutionAttempt：固定 taskRevision/targetRevision/configDigest；重试新 ID 并带 previousAttemptId，附着只读原记录。状态变更保存新 revision，不抹去历史。
- EvidenceItem：§5.1 来源、时间、截断、脱敏、授权域必需；原文受限时 availability 明确标记。sourceEventId 去重仅在同 attempt/source 内；不同域不共用可读取引用。
- EvidenceSnapshot：冻结 contractRevision、attemptIds、sourceWatermarks、coverage、gaps 和 evidenceRefs；manifestDigest 使用规范排序 JSON 的 SHA-256。封存内容只读，新增材料产生新 snapshotId。
- EvaluationRun/Finding：§5.1/§5.3，必需 summary.deliveryVerdict 和 assessmentStage；final 不等于 pass。规则输出只引用快照内证据。EC03 计算权威聚合，不由前端或上传报告决定。
- ReviewRevision：可信人工入口身份，追加 reason/decision/previousRevision，不修改原 finding。Agent 工具禁止 review。
- 只支持当前 schema 写入；未来 schema 拒写并保留原件。尚不存在更旧的评估 schema，不虚构 v0 迁移；版本 1 报告在后续规则升级时保持只读可读。

沿用 plugin_message/requestId，不另建 RPC。M1 操作名：list/get/readEvidence/export/createContract/reviseContract/importEvidence/collect/seal/evaluate/review；EC01 是仓库内部 API，不提前暴露未接线操作。配置版本不符返回 VERSION_CONFLICT。同域同 requestId 与同输入返回原响应，异输入冲突；重启不重复提交。幂等回执和对象同一原子提交，不存在对象写入成功但请求索引尚未提交的重写窗口。

错误包含 code/stage/retryable/missingConditions；固定 PERMISSION_DENIED、CAPABILITY_UNAVAILABLE、EVIDENCE_GAP、SCHEMA_UNSUPPORTED、LIMIT_EXCEEDED、VERSION_CONFLICT、EXECUTION_UNKNOWN、VERIFIER_ERROR，另以 INVALID_INPUT、STORE_LOCKED、STORE_CORRUPT、IO_ERROR 区分输入/仓库故障。retryable 不是自动重执行授权。

| 入口                                       | 最小权限与执行守卫                                                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| list/get/readEvidence/export               | 同 principal + workspace；对每个对象及传递引用重新校验；不接受任意路径；分页脱敏；导出返回内容，由已有保存入口写指定位置 |
| create/revise/import/collect/seal/evaluate | 另需本地写权限；工具执行侧计划/只读/委派门禁；evaluate 只读已封存证据，不采集/运行                                       |
| review                                     | 同域写权限 + 宿主可信人工上下文，工具调用一律拒绝                                                                        |
| 后续 start/verify/sync                     | M1 不开放；分别要求执行、可信核验、数据空间写授权，不能从 evaluate 权限派生                                              |

## 资源上限与性能验收（实现前冻结）

| 项目          | M1 默认硬上限/验收门槛                                                                                     |

| 单证据/单记录 | 原文单项 1 MiB；序列化单记录 2 MiB；超限拒绝或有明确 gap 的分片，不静默截断                                |

| 单快照        | 最多 1,000 个证据引用；不在封存时加载全部原文                                                              |

| 采集开销      | 每种负载 5 次开启/关闭；中位耗时增量 ≤ max(关闭中位数 × 20%, 50ms)，CPU 增量 ≤ max(关闭中位数 × 25%, 50ms) |

[EC00-baseline.json](EC00-baseline.json) 记录既有 goal-evidence 摘要函数三类输入各 5 次的读取成本（15 次实际执行），仅为当前模块成本参考，不是 Agent 运行、采集开销或 AC39 通过证据。新采集器与报告延迟尚未实现，保持未测；不以该摘要性能替代 EC04 对照。
