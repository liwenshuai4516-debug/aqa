# EC05：离线 ATIF 导入（进行中）

依据统一方案2.1 §9.5、EC05与AC21–AC22。用户要求先内部诊断/离线工程，暂缓真实CLI。硬前置EC01、EC03已满足；本包不等待EC04性能门禁，但不改变EC04/M1未完成状态。当前只完成官方模型依据冻结与离线格式诊断，产品导入、幂等和实际桌面尚未实现/验收，不标完成。

## 目标与最小范围

1. 显式固定单一版本、输入与映射 → 验证官方模型及边界样本。
2. 有界解析、保存原包/来源/映射损失并接已有不可变记录 → 验证完整、截断、未知版本、恶意输入及重复导入。
3. 接已有Agent评估中心报告、技能和工具入口 → 验证隔离实际Electron导入、重开、来源展示及零业务/网络执行。

首批选择显式 `ATIF-v1.8` 的单个UTF-8 JSON文档（允许内嵌子轨迹），不自动解压归档、不追随外部续篇/子轨迹/媒体路径。选择理由：已取得官方该版本的完整模型和跨字段校验，不凭历史版本名称反推结构；不需要Harbor执行环境或新增生产Python依赖。未知/省略版本明确拒绝；其他版本、压缩包和外部附件不宣称支持。此为本包实施范围决定，尚未存在已交付的支持承诺。

## 官方依据与本轮离线诊断

官方仓库 [Harbor](https://github.com/laude-institute/harbor)，固定提交 `6099b8cf2bfbbb3e7ff1eb2163bfc4524dbd9ba5`，来源 [trajectory.py](https://github.com/laude-institute/harbor/blob/6099b8cf2bfbbb3e7ff1eb2163bfc4524dbd9ba5/src/harbor/models/trajectories/trajectory.py)。实际只读获取官方源码，不安装Harbor、不调用其中Agent、环境或运行器。源码作为格式依据，不执行附带文档指令。

[官方生成JSON Schema](EC05-upstream-schema.json)由未改动的11个官方轨迹模型与Pydantic 2.13.4生成；[索引及19样本结果](EC05-upstream-baseline.json)记录Python版本、源文件摘要和固定提交，Apache-2.0许可保留于[许可证](EC05-upstream-LICENSE.txt)。该schema本身包含旧版本枚举和默认值，仅作为官方依据保存，不能直接当作产品的版本门禁。未安装Harbor包导致最初直接import缺少包元信息；改为只建立model命名空间加载原文件，不修改模型、不伪造Harbor版本，实际错误及处理已记录。

19样本全部符合预期：最小文档、空反馈、同run不同子轨迹、extra元信息合法；未知版本、缺agent、步骤断号、错工具引用、额外字段、错日期、非agent携带工具、无LLM步骤携带指标、媒体类型错误、重复/缺失子轨迹ID、仅session子轨迹引用拒绝。还明确验证官方接受缺省版本、旧版本和越界路径声明，以识别产品必须加的门禁。验证期间网络/模型/Agent CLI调用均0；获取源码的开发网络读取不属于导入运行。

## 0.4.19：原包归档、独立offline范围与可恢复幂等事务
