## 决定及契约细化

- 采用单写者、原子不可变 JSON revision；请求回执随对象一起提交，索引由记录重建，避免双文件请求索引造成丢回执重写。
- 七类实体共用 envelope；`kind+id` 对应设计的各实体 ID，Ref 对应实体 ID+revision。无额外 Trial、评分中心或执行循环。完整磁盘映射见插件 README；当前没有跨端类型，后续类型仍只能放 server/protocol.ts。
- 正文按授权域+内容摘要单独复用，先落 blob 再落引用；引用摘要随封存固定。不能因内容相同扩大读取权限。
- schema/路径/引用/权限/状态在写入前校验。trusted authorize 是唯一身份提供者，合成 WeakMap 上下文用于工程测试；真实入口不接受请求体 owner。
- 不在恢复时推测任务状态、重放业务、自动清理失败证据或抢锁。未知 schema/损坏文件/临时残片保留且阻止新写入，正常已提交对象仍可读。
- EC00 读取预算在仓库图遍历也执行；增加 64 层上限防深引用耗尽栈。它是资源限制细化，不改变 verdict/权限/聚合。未做性能验收或放宽既定门槛。
- 导出移除请求回执和授权域、保存派生摘要与来源摘要。已知凭据模式在存储前脱敏，无法识别任意无标记秘密；来源采集仍必须避免个人凭据。脱敏后的请求内容用于幂等摘要，不保存已识别凭据值的摘要。
