用户明确暂不做真实 CLI 实测，只完成内部诊断和离线工程验证。使用可信 Node 合成 CLI、全新临时目录、合成文件及监听本机回环的网络桩；不读取个人配置/凭据，不安装运行时，不调用模型或真实 Agent CLI。

1. 固定可信 fixture 与实际二进制，验证目录、环境、argv/stdin 和网络限制。
2. 制造 detached 子进程，验证取消能否收尾全部尝试进程，旁路进程不受影响。
3. 保存正反证据；只有完整 containment 满足时才继续产品生命周期实现，不以诊断脚本退出 0 代替 EC06 验收。

## 观察结果

`tests/agent-evaluation-isolation-test.mjs` 调用 `/usr/bin/sandbox-exec` 的默认拒绝策略；只允许该 Node、必要系统/运行库目录、合成工作区及有限设备文件。Node 启动需要对祖先目录授予 literal 读取：可列出这些目录的名称，不能声称路径完全不可见；未给个人目录授予读取权限。此策略只是本机可行性候选，不是通用客户端安全配置。

## 2026-10-26：宿主有界日志组件

基线`f86935a7fdd67171df8b5c92b4cbe97bbaafd079`，范围是EC06/AC25的真实组件实施及AC26的最终文本不等于退出子项。新增`server/external-evaluation-log.ts`，供后续宿主执行生命周期使用。现有PluginHost.bash会按空格拆分参数、一次性收集stdout/stderr，不能复用为所需的原样argv、独立持续流和恢复接口；本轮先实现必要流组件，没有增加新宿主API或ExecutionAdapter占位接口。

`ExternalEvaluationLog`是标准Writable：宿主须先授权专属证据目录，显式创建独占/no-follow原始文件并指定stdout/stderr、原始字节/行字节/解析条数预算；上限分别1MiB/64KiB/1000条，highWaterMark固定16KiB。它不会创建进程、读取个人配置、推断执行状态或删除旧证据。每个成功OS写入片段按实际bytesWritten更新SHA256及解析范围，处理短写，文件与目录均fsync后才标durable；错误/中断等待在途写入并关闭自有描述符。

原始数据按字节原样保存，解析记录只引用已落盘的[start,end)字节区间，行上限含正文不含换行。完整行严格校验UTF-8后解析JSON；stdout非JSON/非法UTF-8保留gap，stderr合法非JSON保留text，原始字节始终可回查。此处是UTF-8执行协议解析，不是附件预览的GBK回退。JSON嵌套超过64层或数值超出JavaScript有限范围时保留原始字节并标解析预算缺口，避免后续clone溢栈或Infinity被序列化为null；普通有限数值遵循JavaScript JSON数值精度，不将其当可信业务测量。中断即使恰好位于行边界也保存未知尾部标识，不把已处理字节数当作完整上游总长度。跨块UTF-8/半行JSON重组、CRLF及无末尾换行均覆盖。超长单行只占固定解析缓冲，恢复后续行；解析条数超限保存聚合缺口。原始上限后继续遵守流背压并排空输入，累计未保存范围，不把被截断的最后半行当完整JSON。
