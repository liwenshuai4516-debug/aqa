# EC06 — 原生隔离候选可行性诊断

依据统一方案 2.1 §9.1–9.3、EC06 与 AC23–AC27。2026-10-25，基线提交 `3fe28c5fc7268ce6c15bdf1c70dd286f644be5d4`，插件仍为 0.4.20。本包仅新增可复现诊断与证据，没有增加产品执行入口或修改插件，因此不升级插件。

## 范围、环境与成功标准

用户明确暂不做真实 CLI 实测，只完成内部诊断和离线工程验证。使用可信 Node 合成 CLI、全新临时目录、合成文件及监听本机回环的网络桩；不读取个人配置/凭据，不安装运行时，不调用模型或真实 Agent CLI。

环境为 macOS arm64、Node v23.10.0；原生二进制真实路径、摘要、内核和运行库目录记录在原始结果。只检查 PATH 中 docker/podman/colima/limactl/qemu-system-aarch64/orb 六个名字，均未发现；这不能证明全机不存在其他虚拟机。没有已配置且验证的容器/VM 后端。已有 sandbox-service 是工作区复制及工具限制，不能视为 OS 隔离。

1. 固定可信 fixture 与实际二进制，验证目录、环境、argv/stdin 和网络限制。
2. 制造 detached 子进程，验证取消能否收尾全部尝试进程，旁路进程不受影响。
3. 保存正反证据；只有完整 containment 满足时才继续产品生命周期实现，不以诊断脚本退出 0 代替 EC06 验收。

## 观察结果

`tests/agent-evaluation-isolation-test.mjs` 调用 `/usr/bin/sandbox-exec` 的默认拒绝策略；只允许该 Node、必要系统/运行库目录、合成工作区及有限设备文件。Node 启动需要对祖先目录授予 literal 读取：可列出这些目录的名称，不能声称路径完全不可见；未给个人目录授予读取权限。此策略只是本机可行性候选，不是通用客户端安全配置。

| 探针                                | 实际观察                                                                                        | 边界                                  |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------- |
| 工作区读写、argv/stdin              | 允许且逐字一致，shell 字符未展开                                                                | 没有启动 shell                        |
| 合成外部兄弟文件读写、越界软/硬链接 | 全部 EPERM，原合成文件保持原值                                                                  | 未探测个人文件                        |
| 回环 TCP                            | 父/子均 EPERM，监听桩收到 0 连接                                                                | 未尝试外部网络；不外推所有网络类型    |
| 子进程继承                          | 同样拒绝越界文件/回环网络                                                                       | 继承文件/网络限制不等于可完整取消     |
| 禁止 fork 对照                      | 子进程创建 EPERM                                                                                | 不能以禁用子进程缩减 EC06 验收范围    |
| 环境                                | HOME/TMPDIR/config/cache 指向新工作区，NODE_OPTIONS 未继承                                      | 仅合成 Node fixture                   |
| 原进程组取消                        | 根进程 SIGTERM 退出，detached 子进程继续运行并被重新挂到 PPID 1                                 | **containment 不满足**                |
| 收尾与旁路                          | 旁路进程存活，随后通过自有 ChildProcess handle 终止；detached fixture 2500ms 自行退出并确认消失 | 未按孤儿 PID 发信号，没有全局进程清理 |

最终反例根 PID 59537/PGID 59537，子 PID 59539/PGID 59539。对本诊断刚创建且仍存活的根进程组发送 SIGTERM 后，子进程仍存活、PPID 变成 1。前后证据包含开始时间与 nonce 命令身份，未把 PID 数字单独作为所有权依据。其自身 watchdog 退出只保证合成夹具不残留，不能解决任意客户端收尾。

诊断结论 **PASS** 表示控制探针与反例均被复现；执行后端验收 **BLOCKED / UNSUPPORTED**。EC00 路线结论保持 **缺条件阻塞**，不采用 `sandbox-exec + 进程组取消` 作为正式后端，不降级到宽权限宿主执行。

本机 SDK 头文件明确说明 kqueue 的 NOTE_TRACK/NOTE_TRACKERR/NOTE_CHILD 自 macOS 10.5 起不再支持；没有将它们假定为可用的逃逸进程追踪方案。

## 2026-10-26：无网络 Linux VM 隔离候选

[本轮证据](EC06-vm-diagnostics.json)：macOS26.6.2 arm64的硬件虚拟化与Swift6.3.3可用。Lima2.2.1元数据可读但公开二进制下载超时，未安装或作为第二后端实现。改用系统Virtualization.framework做唯一离线候选：可信Swift测试supervisor仅附串口与熵设备，2CPU/512MiB，network/share/disk/vsock全部为0，45秒自有诊断watchdog。不使用sudo、不注册后台服务、不改变签名/更新身份或个人安装；仅对本轮编译的独立测试二进制临时ad-hoc签名virtualization entitlement。

公开Alpine3.22.7 aarch64 virt ISO共80,644,096字节，SHA256与官方HTTPS发布清单一致；EFI zboot内核直接启动失败，提取已固定gzip payload为原始ARM64 Image后成功。镜像、内核和initramfs逐项固定摘要；每次测试开始/结束均核验，不把HTTPS清单当作独立签名验证。新增`prepare-vm-runtime.mjs`只从精确已知ISO提取三个启动文件到全新目录，不自动下载/安装。大镜像保留外置目录并登记hash，不复制进主仓或原件归档。

最终探针并行启动first/peer：guest仅有lo，访问宿主回环监听端口失败、宿主连接0；合成宿主canary不可见且不变，first的RAM文件在peer不存在。first内可信shell夹具的setsid子进程另建进程组、忽略TERM；原根PID收到TERM后，子仍输出至少三次心跳。随后只给本轮拥有的VM supervisor ChildProcess handle发SIGUSR1，调用VZ.stop；框架回调确认state0、supervisor退出0，串口不再输出，peer与宿主旁路进程保持存活。新建fresh VM没有前次文件/脚本；三台最终均明确停止、退出0，无兜底SIGKILL/watchdog。guest PID不作为宿主PID使用。

这为所述离线候选证明整机containment/收尾，**不是EC06产品执行后端通过**。新guest是Linux，与原生macOS不同；不从一次可信shell夹具推定任意CLI安全/兼容。原sandbox-exec反例亦完整复跑，原候选仍BLOCKED。初次完整诊断因BusyBox彩色ls断言失败，改精确printf；第二次因绕过init而缺/dev/null，补guest devtmpfs后通过；随后格式化/固定摘要及独立准备运行时分别完整重跑通过。全部失败原件保留，不计通过。

完整五配置typecheck、3文件99项相关回归、lint、Swift格式、协议结构/v33与size通过，历史tag启发式SKIP；clean仅预览零删除。104份源码/原始输出/检查/依赖来源索引归档并逐文件hash复核。首次归档准备因旧反例中的故意软链接中止，59份部分归档另行保留；最终只保存链接元信息，不跟随复制。没有产品文件/版本变化，仍0.4.32；本轮未运行Electron、真实CLI、外部模型或业务写入。
