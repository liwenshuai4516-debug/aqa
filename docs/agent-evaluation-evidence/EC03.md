## 本次已实现的基础

- `registry.mjs`：EvidenceAdapter / Evaluator / EvaluationProfile 注册；精确 ID+版本；批量原子登记；重复、缺依赖、循环依赖、任务类型、配置与 schema 子集校验。只注册可信代码，不执行导入内容；冻结副本，后续修改调用方对象不会改已注册配置。单个 profile 不允许同一规则的多个版本，旧版本注册和旧报告保留。
- `evaluate.mjs`：只读快照视图（1,000 条/8MiB/2秒），冻结契约、证据和配置；不提供宿主、store、shell、网络、runner 或模型服务给规则。按需校验声明的 requiredEvidence 和输出字段/引用/条件绑定。来源修订冲突或未经证实的适用性不能产生确定结果；target-reported 不能升级成 verified 必需条件通过。
- 作业 queued、running、取消请求保存为本地证据事件；结束报告单独原子保存。输入 requestId 幂等；中断后查询为 unknown，不自动重跑；明确新请求才能重评。取消通过代次和 AbortSignal 拒绝迟到结果，关闭停止新作业并取消活动评分。报告保存失败为 failed；发布成功丢回执后可回查已保存报告，不重评。
- `aggregate.mjs`：必需目标、约束、交付门禁分开；目标未知不掩盖已知必需失败，正确拒绝不直接变成违规。建议项不进入硬门禁；无法证明不适用的条件仍在分母。统计对象为 findings，列 planned/executed/determinate/unknown/notExecuted/errors/excluded、确定项通过率和判定覆盖率，零分母为 null。executed 基于真实评分函数调用，缺证据的预检跳过不算已执行；取消/未执行/缺证据与评分器错误分开计数。
- `schema.mjs` 在 schemaVersion 1 下新增可选 metrics、configuration、job 及 summary 统计字段；原基础报告仍合法，原记录不迁移或覆盖。插件版本 0.2.0→0.3.0。

profile.required 在本实现中限定为“必须成功处理的评分器”，并非增加用户业务条件。它的缺口令交付待核验；业务 pass/fail 仍来自冻结契约。规则配置 schema 支持发布代码需要的 object/array/基本类型、逻辑组合、数值/长度约束、枚举；拒绝未知关键字、外部 `$ref` 和代码，未承诺任意 JSON Schema 方言。

同步可信 JavaScript 不能被同进程计时器抢占：异步等待按预算中止，同步返回后核对单调耗时并拒绝迟到结果。没有 CPU 硬隔离声明；不可信评分代码不支持。当前尚未实现 F08 的任务阶段/费用指标，此处单调计时仅用于评分作业预算。
