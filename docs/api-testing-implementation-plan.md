# 接口自动化测试分阶段执行计划

状态：2026-10-21 已完成 P0-1 的 fixture 可行性验证，真实目标因隔离缺口阻塞；P0-2 已实施受控 fixture 接线，详见下方执行记录；P1-1 已完成导入/编译模块验收；P1-2 评审控制工程验收通过，实际模型待 P1-4；P1-3 及以后尚未验收。详细证据见 [P0-1 验收记录](api-testing-evidence/P0-1.md)。原设计复审不计作功能验收。

## 1. 执行目标与文档优先级

先让一条业务完成“导入 → 生成 → 评审退回/修正 → MCP 执行 → 异常分析 → 修复后复测 → 报告”。再支持保存后的用例/脚本跨任务重复执行，最后增加定时运行。主流程必须形成可复现证据，不能用搭好界面或安装了 MCP 代替验收。

用户最新决定与 `AGENTS.md` 的强制规则优先；本计划定义实施范围、顺序和验收，另外两份设计文档描述完整目标。发现矛盾先修正文档，不按较大的目标擅自扩展本阶段。任务中的路径是建议落点，新增前核对实际工程；不得预建空目录或占位模块。

优先级：**必需**为主流程或后续阶段不可缺的前置；**随后**在主流程验收后实施；**延后**须有实际需求或样例才启动。P0–P4 是阶段编号，不表示全部要在一次任务中做完。

| 依赖图、语义增量解析、历史根因自动复用同时进入存储阶段                             | 先精确 hash 复用与整包新版本；语义优化和根因缓存放 P4                  | 低成本重复执行不依赖复杂语义缓存；服务版本常无法准确获取       |

| 所有证据截断都等同于测试失败                                                       | 区分执行记录缺失与已校验响应的展示截断                                 | 断言结果、诊断完整性、清理结果应分别展示                       |
| 提前建设 JUnit/全新报告工作台/多实例可靠调度                                       | 首期 Markdown + JSON；复用已有展示，JUnit 随 CI 需求增加；仅单实例     | 用户尚无这些前置需求；文件持久化不能承诺分布式 exactly-once    |

这些是范围收敛，不删除最终多格式、回放与定时能力。真正需要保留的复杂度是：版本绑定、执行授权、失败证据、取消与未知结果处理，以及评审循环上限。

## 4. 全阶段约束与开发规范

1. **业务事实**：断言必须有契约或已确认业务规则依据。未定义的错误码、权限行为和业务关系列待确认；不得因为失败放宽断言。业务代码修复与外部提单需独立授权，闭环允许 `awaiting_fix/blocked`。
2. **执行边界**：目标使用明确配置的 test/staging 地址、测试租户和凭据引用；模型不能选择任意目标、读取个人凭据或执行任意脚本。P0 验证重定向、文件访问、进程环境和网络出口约束；单纯字符串检查不能冒充沙箱。隔离能力未证实只运行自包含 fixture。
3. **首期断言**：状态码、JSON 字段存在/类型/枚举/明确值、已确认状态转换；固定模板使用成熟断言库。完整 JSON Schema 合规不是首期承诺；未支持关键词明确列未覆盖，若其为所选业务关键断言则该项阻塞。
4. **控制与状态**：权限、资产 hash、轮次、时间、调用限额由程序核验。默认评审最多 3 次，连续 2 次无改进停止；执行后用例修订最多 2 次。每轮受同一总体预算约束，不能递归启动新任务清零预算。首期不自动重试接口请求。
5. **取消与重复**：只停止本 run 的进程；保留首次失败和每次 attempt。执行前落盘 run 身份，未确认结果标 unknown；双击、断连、超时和重启不能自动重发写请求。取消不承诺回滚业务数据。
6. **凭据与产物**：密钥仅引用/运行时注入；集合、脚本、报告、日志与模型输入均不得携带明文凭据。持久化前脱敏，敏感原始响应只在内存完成校验。原始输入含凭据时保留净化副本，不为“可重现”长期留存密钥。
7. **架构**：优先一个 `plugins/api-testing/` 功能包；宿主只补已证明缺失的受控调用/生命周期接缝。协议单源、工具注册、版本、SDK、UI 国际化按模块规范联动。禁止复制现有客户端、解析器或调度器；禁止顺便重构目标模式。
8. **技能**：工作流、评审、结果分析按需加载。评审使用独立无执行工具上下文；技能中的指令不能替代服务端硬门禁。创建技能时读取适用 skill-creator 规范，个人技能不视作已分发依赖。
9. **测试与交付**：按仓库规定依次格式化本次文件、typecheck、相关单测，再 lint、协议检查和差异检查；依赖/构建链变化加 build，公共权限/生命周期变化加相关集成与核心冒烟。隔离端口 ≥8900、临时 data-dir，只清理自己的进程；不读写个人测试配置。
10. **变更纪律**：每个任务独立可审查提交，只暂存本任务文件；按持续授权推送当前分支并核对远端 SHA。未验证平台、SKIP、模型未调用、真实接口未执行须分别报告，不能用 fixture 通过冒充业务上线。

## 6. 各阶段的具体范围与取舍

### P0：先消除执行选型风险

采用本地 stdio 专属 runner；Newman CLI 仅作对照实验，不成为第二条生产执行路径。P0-1 先测上游原生行为，再做只覆盖本地输入、脱敏结构化输出、生命周期的验证性适配。记录上游版本/许可证、改动文件、所需依赖、实际网络访问与剩余缺口。

以下任一情况停止当前候选的产品化：需要改 Newman 内部、重做 HTTP/脚本引擎、强制上传本地测试数据、无法保留关键证据、无法终止自己的运行，或需要持续维护上游无关模块。输出阻塞决策，下一步先评估另一成熟 MCP；不能悄悄退化成自行写 HTTP 测试引擎，也不继续堆 UI 掩盖失败。选型更改有明确依据后同步计划，用户已授权选择服务，无需为普通技术取舍反复询问。

宿主接线涉及的最小接口包括调用者身份、server/tool 白名单、冻结 run 引用、取消信号及结果引用；具体 schema 由 P0 证据确定。P0-2 使用手工审定并冻结的最小包验证门禁，不依赖尚未实现的模型生成流程。MCP 工具成功返回并不代表用例通过。测试连接使用独立配置，生产运行必须有受控入口而非依靠模型“自觉不绕过”。

### P1：先一条真实运行的业务链

建议 fixture 为“创建记录 → 查询 → 更新状态 → 查询 → 删除清理”，规则写入契约/业务说明，ID 从本次响应提取。准备正常版本与故意违反契约的版本，分别验证成功、发现缺陷、修复后复测；fixture 修复不等于获得修复用户业务代码的授权。

冻结包先包含 `manifest.json`、净化来源、`cases.json`、实际 `collection.json`（含脚本）、`review.json`。run 目录保存运行身份、脱敏 `results.json`、`findings.json`、`report.md`；包内带 schemaVersion、hash 和必要工具版本。它们是一次执行所需的文件，不是独立资产服务；不要求数据库、全文搜索、跨重启续跑或调度系统。

首期串行、单环境、单项目一次只跑一个 run；通过保守互斥避免先造资源调度器。用例错误修订必须有契约证据并重新评审；真实业务缺陷留下修复要求。模型仅生成/评审/分析，编译、版本校验、执行和统计由确定性代码负责。

模型调用额度与真实业务环境是外部前置条件，缺少时可完成确定性路径与 fixture，但不得勾选真实模型/业务验收。需要的业务输入为脱敏契约、test/staging 地址、测试数据/权限范围、凭据引用、至少一条明确业务规则；不要让用户提交明文密钥到文档或聊天。

### P2：够用的复用，不提前做数据平台

整体套件版本是首版发布单位。用例、断言、脚本仍有包内稳定 ID，便于跟踪失败，但不单独建设版本服务。修改任一受评审文件产生新套件 revision；精确 hash 未变化则直接复用。输入变化先待核验，不自动耗费模型重生成；自动识别“不影响语义的变化”后置。

使用独立持久目录和可重建索引，单实例写入，拒绝多进程同时写入同一根。先校验暂存文件再发布完成 manifest，最后更新索引；关键写失败不能宣称完成。P1 迁移采用复制、校验、导入，失败保留原件。归档优先于删除，不默认开启自动清理历史证据。

“历史回看”不发请求；“再次执行”始终新建 run；“重新分析”只追加分析修订。首期管理可按已知套件/运行定位和列表浏览，不增加全局搜索、复杂对比、编辑器或对象存储。

### P3：固定策略优先，避免过度配置

首版仅服务器本地时区；同项目单 run 互斥，重叠和漏跑均 skip，不提供补跑策略选择。每次计划触发记录 `projectId + scheduleId + revision + dueAtUTC`，执行前持久化认领；不能以回调实际到达时间代替计划触发时间。保留跳过原因。服务需持续运行，不承诺桌面关闭后仍执行。

宿主需最小补齐触发上下文、保存失败反馈与后台 Stop 同步。业务定义/宿主声明不一致先暂停；启动后未完成运行记 unknown，人工核对前不自动续跑。不要为当前单实例需求引入分布式锁或恰好一次执行承诺。

授权独立于某个打开的聊天，但不是绕过权限的通道。成功路径纯程序执行/报告；异常分析预算独立，失败不触发重新执行或整套生成。外部通知和缺陷平台不属默认范围。
