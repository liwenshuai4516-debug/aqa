# U03 / U07 实施与验收

日期：2026-10-27。范围：原生 `pi-ui-testing` 0.1.20、共享宿主接入与 macOS arm64 Electron 验收。工程功能已实现；性能目标及真实模型自主规划未验收，不关闭 M1/M2。

## 实现与边界

- U03：`status.stage_inputs` 返回最新任务/范围/资产/选定批次/报告引用；`handoff(task_id,stage,output_refs)` 重读状态并复用原 checkpoint 校验，重复原产物只查询，冲突/取消/未知副作用停止。`directory` 只返回当前技能。
- U03：`continue-execute(task_id,authorized_asset_ref)` 仅将 completed/new 衔接为稳定 ID 的独立 execute 任务，核对完整资产、批准及现行诊断并显示全部 case_ids。record 不自动衔接；只登记，不启动浏览器，不授予入库/绑定/同步权限。
- U07：`ui_design_diagnose/reuse` 只查询当前权威证明并核对原诊断计划/全部已登记输入；旧规则、配置/源码/数据/环境声明变化、未知诊断均拒绝。不能推断未知现场变更相同；每批正式环境/数据预检仍执行。升级使旧诊断规则证明失效，须正常重新诊断，不降级复用。
- U07：`ui_result_analysis/analyze-task` 只处理选定已结束批次。同观察签名可以分组，每个非 passed 实例仍须完整 findings/本批次证据；全部 attempts、flaky、取消、清理和缺口保留，不从分组推断共同根因。
- 全 passed 自动输出简洁确定性摘要、空 findings 及正常报告候选；止于独立结果评审。宿主把返回的 workflow 直接投影到原看板；无额外 status。partial/失败/未经评审均不能冒充最终批准。子批次分析不替换父批次。

不新增调度器、业务 runner、跨请求缓存或放宽评审策略；技能仍维护在原生包。0.1.19 是本地未交付中间包。

## 性能对照

冻结端点为同一个合成正式 run 的已登记 analyze 任务 → 正常报告候选/待结果评审；同资产、范围、实例、依赖、角色及批准等级。每轮5组、交替先后顺序，全样本保留；预备诊断和正式浏览器执行在计时外，原run摘要前后不变，无新增浏览器/模型调用。测量脚本为 `tests/ui-u03-u07-comparison.mjs`。

| 最终路径                    |    0.1.18 |    0.1.20 |
| --------------------------- | --------: | --------: |
| 确定性调用（不含共同start） |         4 |         1 |
| 5样本耗时中位数             | 284.81 ms | 330.48 ms |
| 最大耗时                    | 311.18 ms | 591.59 ms |

调用减少75%，耗时中位数增加16.0%；样本波动较大且存在退化。最初0.1.19中位数289.46→443.47ms；删除新增路径两处紧邻重复工作后，含额外status的0.1.20为286.37→348.18ms；再直接投影回执后如上。各轮完整原始值均保留，不能挑最好样本宣称提速。

额外按任务ID读取当前状态、锁/取消与引用归属核对仍有机械成本；尚未用分项计量证明每项占比，不把全部退化归因某个实现。当前保持这些正确性检查，不为毫秒级结果增加缓存。性能目标未达标，不声称20%收益；首次发现/完整Agent规划/业务执行/独立模型评审端到端对照未执行，不将本脚本当M2通过。
