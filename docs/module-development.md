# 模块开发规范

[文档导航](README.md) · [模块地图](project-map.md) · [开发工作流](development.md) · [AGENTS.md](../AGENTS.md)

适用于新增功能和扩展现有模块。本文提供操作步骤；强制约束以 `AGENTS.md` 为准，架构细节查对应专题。小改动可直接在任务说明中记录设计，不要求每次新建一份文档。

## 1. 开发前明确目标

先阅读相邻实现、接口契约和现有测试，写明用户操作、预期结果、改动范围与验收证据。未定义行为标记待确认，不能自行补成需求。修复缺陷先复现；功能开发先定义可验证的成功标准。

可复制以下清单作为任务或模块设计说明：

```markdown
### 功能：<名称>

- 用户场景与目标：
- 本次范围 / 不包含的工作：
- 已知事实及依据（需求、文件、接口、测试）：
- 假设 / 待确认行为：
- 所属模块与选择理由（内核 / 插件 / 桌面）：
- 入口与联动文件：
- 输入、输出、错误和权限边界：
- 状态归属（全局 / 项目 / 会话）、持久化与旧数据兼容：
- 生命周期（创建 / 切换 / 取消 / 断连 / 销毁，按需填写）：
- 支持的引擎、平台与远端工作区限制：
- 验收用例（操作、预期、验证方式）：
- 回滚方式及数据影响：
```

## 2. 选择扩展位置

| 功能性质                                        | 优先位置                                 | 选择依据                                             |
| ----------------------------------------------- | ---------------------------------------- | ---------------------------------------------------- |
| 可独立启停的集成、视图或工具，现有宿主 API 足够 | `plugins/<id>/`                          | 复用插件生命周期、权限和 UI 插槽，降低核心耦合       |
| 会话生命周期、协议、审批、跨引擎公共行为        | `server/` + 必要的前端接线               | 属于宿主能力，不能靠插件或前端绕过服务端规则         |
| 现有业务的展示与交互                            | `web/src/components/` + 对应 Hook/纯函数 | 优先扩展已有组件；不复制协议、权限或业务状态         |
| 操作系统窗口、原生对话框、桌面进程生命周期      | `desktop/` + 必要的桥接                  | 先核对桌面交付范围；可共享业务继续由 Web/server 承担 |

插件开发起点见 [SDK 脚手架](../plugin-sdk/README.md)。需要新增宿主 API 时，先说明现有 API 缺口和权限边界，再改宿主；不要直接访问宿主内部对象来绕过接口。

## 3. 模块边界与命名

- 一个模块围绕一项业务职责组织；入口文件负责校验与接线，业务规则放所属服务，可独立验证的计算放纯函数。不要把新增逻辑全部堆进 `agent-service.ts`、`index.ts` 或 `use-chat.ts`。
- 依赖通过明确参数、现有接口或注册机制传入；避免隐式读取另一会话的可变状态、循环依赖和复制相邻实现。只在已有重复或确有边界需求时抽公共层，不新建通用框架。
- 服务端与普通辅助模块沿用 `kebab-case.ts`；React 组件默认 `PascalCase.tsx`；Hook 使用 `use-*.ts`；单测 `tests/unit/<主题>.test.ts`；集成/UI 回归 `tests/<主题>-test.mjs`。既有例外按原风格维护。
- 文件头或模块说明应能回答“负责什么、入口在哪、持有什么状态、如何清理”；简单纯函数不强制重复类型中已有的信息。
- 浏览器代码不导入 Node/SDK 运行实现。跨端类型从协议单源获取；确需共享的纯数据模块不得引入服务端副作用。
- 创建定时器、监听器、进程、订阅或异步任务时，同时实现取消/销毁路径；明确会话切换、断连和迟到回调的归属，防止向新会话写入旧结果。

## 4. 按变更类型检查联动

下表是检查清单，不要求每个功能都修改整行文件。只修改实际涉及的部分，并说明不适用项。

| 变更                    | 必须检查的联动                                                                                                                                              | 验证重点                                                                |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 新增 WS 消息或状态字段  | `server/protocol.ts` → 服务端分发/领域处理器 → `web/src/use-chat.ts` → 消费组件；保持 `web/src/types.ts` 为 shim                                            | 输入校验、错误回执、快照/增量、刷新/重连；破坏兼容时核对协议版本机制    |
| 新增设置/偏好           | 协议类型、`server/client-state.ts` 默认值与读取、`server/settings-service.ts`、设置 UI；如可分享则核对 `server/preset-fields.ts` / `server/preset-share.ts` | 作用域、旧配置缺字段、保存后刷新、敏感字段禁止导出                      |
| 新增可开关内置工具      | 工具实现、`server/tool-manager.ts`、`server/agent-service.ts` 的注册路径、`tests/unit/tool-registration.test.ts`；按路径核对 host factory 和工具闸门        | 关闭时不可调用、审批/计划/委派限制、取消、纯英文提示词与结果大小预算    |
| 覆盖 SDK 工具           | `server/tool-overrides.ts` 及现有单源提示词                                                                                                                 | 扩展实现优先、所有执行路径语义一致，不覆盖掉第三方同名工具              |
| 新增插件或插件能力      | manifest、宿主 API/权限、客户端入口、版本、README；内置市场插件核对 `plugins/catalog.json`                                                                  | 激活/停用/重载、拒绝权限、卸载清理、客户端依赖位于可服务的 `client/` 内 |
| 新增 UI/文案/样式       | 组件、`web/src/styles.css`、`web/src/i18n.tsx` 的 zh/en、`locales/`；如使用插槽则核对 `web/src/ui-slots.ts`                                                 | 明暗主题、窄屏、长文本、键盘/触控、加载/空/错误状态、词条顺序与占位符   |
| 扩展多引擎公共能力      | 分发接口、`server/engine-capabilities.ts`、各引擎会话实现                                                                                                   | 支持矩阵与隔离；不支持时明确反馈，不能只在 pi 实现后宣称全引擎可用      |
| 新增 HTTP/文件/远端操作 | `server/index.ts` 或对应路由服务、鉴权与路径校验、前端 `appUrl()`                                                                                           | 越界/无权限/大小限制、代理子路径、远端与本地语义                        |
| 新增桌面能力            | `desktop/`、preload/前端桥接、桌面范围与批准记录                                                                                                            | 平台兼容、进程收尾、个人数据边界；各平台分别报告实测状态                |

UI 实现细节遵循 `AGENTS.md` §9：复用 `useFloatingPanel`、主题对比度令牌和国际化机制。工具延迟加载保持系统提示词前缀稳定，`details` 不超过 64KB，前端支持缺失时降级。

插件非纯文档修改须递增 manifest 版本，存在 package 版本时保持一致。调试时确认隔离测试 data-dir 中加载的是新代码；复制或使用已有链接脚本均须显式指向测试目录，不默认覆盖个人插件。已跟踪的 bundle 按插件构建流程更新。

## 5. 验证与交付

### 提交前基础检查

先对本次明确列出的文件执行 `npx prettier --write <改动文件>`，再执行 `npm run typecheck`、`npx vitest run <相关单测路径>`，遵守 `AGENTS.md` §9 的顺序；同时运行 `npm run lint`、`npm run check:protocol` 和 `git diff --check`。占位符须替换成真实文件列表，不能直接复制执行。

`npm run format` / `format:check` 的范围由 `package.json` 决定，当前不包含 Markdown；文档需要显式传入 Prettier。纯文档变更检查路径、链接、命令和规范一致性，不为凑覆盖率新建只验证文案的单测；按仓库要求运行基础检查和与所述契约相关的现有守卫，并如实列出未运行项。

### 按风险补充回归

| 变更面             | 回归选择                                                                       |
| ------------------ | ------------------------------------------------------------------------------ |
| 纯函数/状态转换    | 对应 Vitest 用例：正常、异常、边界；缺陷修复增加能复现问题的回归               |
| 协议/生命周期/权限 | 相关 `tests/*-test.mjs`；公共链路变化跑核心或全量冒烟                          |
| 工具注册/提示词    | `tool-registration.test.ts`、`tool-prompt-hygiene.test.ts` 和对应工具/权限用例 |
| UI/样式/文案       | 对应行为测试、样式/i18n 守卫及浏览器交互；词条变化运行 `npm run i18n:check`    |
| 插件               | 对应插件、权限、manifest/目录与版本守卫；涉及 bundle 时验证构建产物一致        |
| 引擎接口           | `engine-interface-conformance.test.ts` 及各受影响引擎回归                      |
| 构建/依赖/发布内容 | `npm run build`；桌面/浏览器扩展按实际范围追加对应构建                         |

冒烟用例使用 `tests/lib/ensure-build.mjs`，不在并行用例内自行重建。测试使用独立端口（≥8900）、临时 data-dir 和隔离数据，精确清理自身进程；真实模型、外部服务与生产写操作必须在授权范围内。详细要求见 [开发工作流](development.md)。

验收记录至少包含：测试对象与范围、依据、环境、已设计/已执行/通过/失败/阻塞/未执行项、关键证据和剩余风险。SKIP 单列，历史结果只作参考；不能用单测通过替代未执行的浏览器或平台验收。

### 完成清单

- [ ] 验收行为有证据，错误、权限、取消及兼容路径按适用范围验证。
- [ ] 新增或变更模块已登记到模块地图、目录参考；专题机制有变化时同步专题文档。
- [ ] 配置、依赖、版本、语言包与生成物按实际变更同步，无凭据或个人数据。
- [ ] 检查差异，仅暂存本次文件；按 `AGENTS.md` §6 提交并推送当前分支，核对远端 SHA。
- [ ] 交付说明列明文件路径、验证结果、未覆盖项和提交号；规则更新后在 pi 中 `/reload`。
