# T34 实际更新器网络异常验收

日期：2026-10-21。对应 T08、A13/A14。基于 T19/D06 的实际 DMG 安装应用副本，macOS arm64。最终 14 项检查 PASS，证据为 evidence/T34-updater-network-final.json/log 和重启截图；v3 的 14 项 PASS 另保留。

## 范围与隔离

独立中文安装路径、工作区、空认证/模型配置及数据目录；没有读取个人认证或发送真实模型请求。副本仅增加测试启动引导、回环 HTTPS 更新配置和独立缓存配置，再导入字节相同的原桌面 main。原 electron-updater、preload 和业务服务实际运行。

测试引导在首个请求之前，为 electron-updater 专用 session 注册证书核对：仅回环主机且指纹等于本轮生成证书才信任。没有改系统钥匙串、全局关闭 TLS 验证或绕过安装签名。私钥留在临时夹具，不归档。实际更新器报告缓存路径 /tmp/pi-updater-network-Oa9kMN/updater-cache，与独立夹具一致。

## 结果

- 当前版本元数据返回 up-to-date；高版本通过原 preload 通知 available。两者均未自动下载。
- 用户下载动作经原桥触发真实 HTTPS 请求。声明长度与实际数据不符时，原更新器以 ERR_CONTENT_LENGTH_MISMATCH 拒绝；业务健康接口仍可用。
- 完整接收但 SHA512 不符时，原更新器拒绝且没有 downloaded 状态；业务服务仍可用。
- 元数据返回 HTTP 503 时，经原检查桥返回错误，应用和业务服务保持运行。
- 项目文件与独立 agent 配置字节保持；完整退出重启后仍是原版本、nord 偏好恢复、项目字节保持。原桌面 main 文件字节相同。
- 最终截图已检查，窗口正常显示工作区、文件及 nord 主题；测试应用正常退出。

前两轮夹具 FAIL 均保留：第一次把证书信任注册在错误 session/过晚位置；第二次虽使用专用 session，但首次启动请求已缓存证书拒绝。两轮没有到达本地 HTTP 服务，不能算网络场景通过。v3 将引导移至原 main 之前后通过；最终运行额外核对真实缓存位置，仍 14 项 PASS。

工程验证：定向格式化、类型检查、2 文件/11 单测和源目录/受保护哈希门禁通过，见 T34-final-*。没有生产源码、依赖、发布包或真实供应商账本变化。来源不明的 bottombar 测试差异保持独立。
