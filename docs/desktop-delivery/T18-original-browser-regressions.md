# T18：原附件与终端浏览器测试

需求：A05 / A06。本轮只修复原测试的定位与前置条件，不修改生产代码、构建或安装包。原浏览器测试针对当前业务构建运行；不是新的实际安装包验收，包内附件与 PTY 证据仍见此前专项。

测试夹具使用独立 agent/data、本地脚本供应商和本机 Chrome；不导入个人账号，不产生真实模型费用。原先首次模型设置浮层通过预置专属本地测试供应商正常满足。首轮临时路径过长导致控制 socket 报 EINVAL，已将 macOS 夹具放在较短 /tmp 路径；原失败日志保留。

附件输入选择器限定聊天输入区，避免同时命中插件内文件输入。文件引用卡按原实现不会渲染 attachcard-content；原测试对 path= 和不包含正文的断言改为观察原 WebSocket 附件消息，断言条件保留，另补 UI 只显示路径且无正文区的断言。没有把正文预览当作注入模型内容。结果：文件拖拽、二进制/SVG 上传与路径引用 **7 断言通过**；图片粘贴、拖拽、上传、删除、纯图片发送与 4000px→1568px 缩放 **9 断言通过**。

终端关闭按钮通过明确名称定位，避免原 class 同时命中重命名按钮；等待目标目录实际出现后才检查，修复文件监视到达时间差。旧测试关闭用过的命令终端后只留未输入的空 shell；原服务通过 countBlockingLive 明确不保留这种空 shell，故不能用它测试“正在使用的终端保留”。本轮先在剩余 shell 实际输入命令，再保留原会话列表与切回恢复断言，生产回收逻辑不变。最后 **24 断言通过**，包括重跑/新 PID、PTY 输入、视图切换、会话切换恢复。早先会话列表超时和截图保留，不改写为成功。

证据：T18-file-upload-browser.log、T18-image-paste-browser.log、T18-terminal-browser.log；前置问题见 first-run / second-run / third-run 日志。最终单独重跑终端，T18-original-ui.json 对应该子集，附件结果保留于第二轮及各自日志，不虚构一次完整合并运行。

验证顺序：定向 Prettier → 全项目 typecheck → 5 文件 / 36 条相关单测通过。来源未明 bottombar 差异未纳入提交或修改。真实目标/委派模型验收另见 T19 提案，尚不能因本地脚本供应商通过而计为通过。
