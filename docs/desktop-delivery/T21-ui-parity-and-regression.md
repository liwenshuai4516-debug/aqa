## 对照方法

新增 `tests/desktop/web-desktop-parity-run.mjs`。实际应用正常启动后附加 inspector/CDP；Web 为真实 Chrome、同一个实际 sidecar 的另一个认证客户端。独立数据、同一中文工作区，1280×860、800×640，DPR=2；通过原 UI 设置语言/主题、搜索设置、重载恢复草稿和偏好，检查窄窗口横向溢出和弹窗边界。

每侧 12 场景：深色聊天及长 UTF-8 草稿、模型/提示词/工具/审批/技能/插件/MCP/布局设置、白色英文聊天、窄窗口聊天及布局。每轮 24 截图、31 断言。设置只截实际弹窗；聊天仅掩码运行指标和时间，隐藏光标，不掩码内容/布局差异。

只读转换原目录 desktop TS，运行同一个当前冻结业务构建/SDK，以隔离宿主展示差异；这不是独立重建原后端。原宿主源码 SHA256 随结果保存，两个独立 agent 路径导致提示词/MCP 路径文本不同，需保留而不能伪造一致。

原始 `T21-parity`、`T21-source-host-parity` 均 24 场景/31 断言通过。Chrome 155 与 Electron Chromium 152 有原生控件渲染差异，逐图差异不等于业务不一致，也不能据结构断言声称像素一致。初始语言、原宿主窗口等待及认证夹具失败均单独保存。

## 排除测试环境差异

Playwright Electron loader 显式带 `--force-color-profile=srgb`。`T21-source-host-parity` 使用该 loader，与实际安装包的正常启动方式不同。`T21-native-source-parity` 改为正常启动原宿主，仅用观察用 did-finish-load 标记确认就绪；测试辅助函数只增加可选入口和就绪标记，其他调用保留默认行为。此轮 24 场景/31 断言通过，设置页与实际包差异约 0.009%–0.33%，根矩形均相同。相关对照见 `T21-native-host-visual-comparison.json` 和联系表。

联系表逐图检查发现聊天快捷短语由首次语言分别种成中文/英文，输入聚焦引起不同滚动，且临时“设置已应用”提示和顶栏更多菜单未稳定关闭。这些旧截图不作为严格同夹具像素结论。随后通过原设置“恢复默认短语”统一为中文，点击输入区关闭菜单、统一滚动请求并等待提示消失；首次重置按钮定位冲突的失败保留为 `T21-aligned-parity`。

最终对齐轮的结果和逐图差异保存为 `T21-aligned-v2-parity`、`T21-aligned-source-parity` 及 `T21-aligned-visual-comparison.json`。不修改生产颜色、CSS、业务设置默认值以追求截图通过。

最终两轮各 24 场景/31 断言 PASS、零供应商请求；12 场景根矩形均相同。原宿主与实际包模型/审批/技能/插件/布局及窄布局截图像素完全相同；工具设置差异 0.0007%。提示词/MCP 因独立 agent 路径差异为 0.3091%/0.2692%，聊天三场景为 0.0467%/0.0482%/0.1281%，可见工作区路径的 /tmp 与 /private/tmp 表达及连接延迟等文本不同。所有像素百分比均按 RGB 任一通道差 >8 计算，没有把这些差异掩掉。已检查最终联系表，无本轮新增布局偏移；不能据此推导其他未覆盖状态。
